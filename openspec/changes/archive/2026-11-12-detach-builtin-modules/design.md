# Design

## Context

四个模块当前由同一个工作台 renderer 渲染。标签拖出监听仅接收 component-example；示例宿主也只持有一套视图、窗口、计时器和落点。导航通过 WorkspaceContext 打开模块，检查器直接读取 Dockview 活动面板的尺寸。

## Goals / Non-Goals

本次交付面向桌面 CMD 的内置模块和已有示例，以四窗共存、混合停靠、单独启动作为验收条件。独立安装包、第三方插件和音乐业务留在原路线图。

## Decisions

- 延续公共宿主方案 B。按固定模块 ID 管理窗口、视图、拖动及交接状态，将原生命中和坐标转换复用于每个来源窗口。选择同一会话随窗口移动，避免创建第二本导航状态。Dockview 的工作台内浮动组无法覆盖关闭工作台后独立运行的需求。
- 工作台保留布局写入权。独立模块入口只渲染相应内容；从宿主接收活动模块及可见尺寸的有限数据，导航操作通过受限的打开模块意图完成。主进程逐项校验模块 ID、来源窗口和操作归属。
- 保留桌面菜单已有选项，追加四模块入口。窗口菜单、快捷入口和模块导航统一定位现有实例。独立窗口关闭后只关闭该模块，可从入口重开。
- 沿用工作台布局键与示例组件协议。宿主确认交接成功后再移除来源；失败按模块回退。首个实现切片验证模块 1 的搜索文字，再扩展至其余模块并覆盖四窗并发。浏览器预览和当前安装包继续使用原有内置面板路径。

## Risks / Trade-offs

多个原生视图可能互相遮挡或误收另一个窗口的尺寸回报。需分别覆盖对话框遮挡、同组切换、交接中关闭窗口、空工作台接回及不同 DPI 的坐标换算。窗口间桥接须有明确用途，模块不得写入工作台布局。
