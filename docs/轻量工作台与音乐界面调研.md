# 轻量工作台与音乐界面调研

FitBay 已支持独立安装 Music、在工作台停靠，以及完整视图、播放栏和后台共用一个播放会话。以下是供讨论的交互候选。这里的「轻量」指减少操作步骤和常驻控件，未实测各项目的内存、启动耗时或安装体积。[FitBay 现行需求](需求与规划.md)

## 工作台如何容纳更多组件

**Flow Launcher 把入口收在搜索框里。** 这个 Windows 启动器把应用启动、文件搜索和社区插件放在同一个检索入口。对 FitBay，可以先用一个具体场景判断是否值得引入命令搜索：工作区已经打开多个面板时，输入「音乐」能否定位正在运行的 Music，再回到原布局。结果行可以同时显示组件名称和「切换到面板」或「打开组件」，让用户按下回车前就知道会发生什么。[Flow Launcher 官方仓库](https://github.com/Flow-Launcher/Flow.Launcher)

**Joplin 给插件指定可加入的菜单位置。** 它的桌面插件可以在内置菜单下创建子菜单，并指定挂载位置。FitBay 可以沿用已有「窗口」菜单管理组件显示，把「加入歌单」等依赖具体曲目的操作放在 Music 内。衡量这个方案时可以问：再安装一个组件后，用户原本熟悉的顶栏是否还在原处？这个交互可以先在第一方组件上讨论，第三方接口仍按现有接入计划推进。[Joplin 桌面菜单 API](https://joplinapp.org/api/references/plugin_api/classes/joplinviewsmenus.html)

## Music 停靠后优先保留什么

**Strawberry 把曲库整理和播放控制作为两类任务。** 它支持管理曲库和歌单、编辑标签，也提供跨平台全局播放快捷键。FitBay 可以借鉴这两条操作路径：整理时展开曲库与歌单，创作时通过现有播放栏确认当前曲目、暂停或切歌。可先比较窄停靠视图中的曲名、播放状态和下一首是否都能直接辨认，再决定是否值得增加快捷键。[Strawberry 官方功能清单](https://github.com/strawberrymusicplayer/strawberry#-features)

## 一次走查

另外两处适合优先试用。工作台首次打开时，把现有的菜单路径提示换成可直接点击的「打开 Music」，仅在已安装 Music 时显示；用户主动关闭所有组件后继续保留空布局。Music 曲库可以在现有列表旁提供「歌曲 / 专辑」切换，利用本地封面和专辑元数据，有多碟或同名专辑时按专辑艺人等信息区分。前者可参考 VS Code 空视图只强调主要动作的规范。后者是针对 FitBay 的设计建议，首期可以仅使用本地封面。在线补封面、补标签、响度分析和转码可按需提供；beets 的插件提供了这些能力的组织实例。[VS Code 视图规范](https://code.visualstudio.com/api/ux-guidelines/views#_welcome-views) · [beets 官方仓库](https://github.com/beetbox/beets)

从已打开的 Music 播放一首歌，切回创作面板，把 Music 收到仅播放栏，切到下一首，再展开曲库。记录三件事：切歌要几步、展开后能否辨认当前曲目、切换前后是否始终只有一个播放会话。这条路径可以用现有功能验证，再决定是调整控件优先级，还是值得增加工作台级入口。[Music 组件开发文档](组件开发.md)
