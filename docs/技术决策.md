## 布局持久化 v1

单人、单窗口、四模块布局是小型 UI 偏好，沿用 profile localStorage；无需文件 IPC、数据库或新状态库。使用 [Dockview 官方 toJSON/fromJSON](https://dockview.dev/docs/core/state/load/)；格式加应用 version=1，先检查模块白名单、组件、树引用、尺寸及版本，再由官方恢复；异常捕获后默认回退。恢复期间不订阅保存，React StrictMode 清理时不读取已经销毁的实例。

onDidLayoutChange 合并 250ms，序列化发生在保存时而非每次鼠标事件；相同 JSON 不重复写入。beforeunload 无条件取最新快照，覆盖尚未触发布局事件或 debounce 的最后一次已完成操作。只承诺正常关闭，异常退出不具备事务性保证。重置是同步完成的布局操作，之后同样自动保存，关闭时也会刷新。

已核查安装版本 dockview-core 8.9.0：grid.serialize 在最大化时临时退出以获取正常尺寸，最后恢复临时状态，并附加 grid.maximizedNode；应用保存/读取时均移除该标记。实测当前 8px gap 下直接 fromJSON 会有约 5px 宽度漂移：serializeBranchNode 保存可见尺寸，而 Splitview descriptor 恢复后再次扣除 marginShare。只在读取时按可见兄弟数补回间距份额，仍由官方恢复；保存保持官方格式。升级 Dockview 时必须复核此适配，不可直接沿用；几何回归包含正常分组、宽高和连续重启，防止累积偏移。

不保存原生窗口位置/大小；不同窗口尺寸下由 Dockview 按比例和模块最小尺寸适配，不承诺跨显示器像素完全一致。未知模块当前整体回退，不尝试保留部分布局；待模块注册表实际扩展再设计格式迁移。
