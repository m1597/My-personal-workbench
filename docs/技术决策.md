## 布局持久化 v1

单人、单窗口、四模块布局是小型 UI 偏好，沿用 profile localStorage；无需文件 IPC、数据库或新状态库。使用 [Dockview 官方 toJSON/fromJSON](https://dockview.dev/docs/core/state/load/)；格式加应用 version=1，先检查模块白名单、组件、树引用、尺寸及版本，再由官方恢复；异常捕获后默认回退。恢复期间不订阅保存，React StrictMode 清理时不读取已经销毁的实例。

onDidLayoutChange 合并 250ms，序列化发生在保存时而非每次鼠标事件；相同 JSON 不重复写入。beforeunload 无条件取最新快照，覆盖尚未触发布局事件或 debounce 的最后一次已完成操作。只承诺正常关闭，异常退出不具备事务性保证。重置是同步完成的布局操作，之后同样自动保存，关闭时也会刷新。

已核查安装版本 dockview-core 8.9.0：grid.serialize 在最大化时临时退出以获取正常尺寸，最后恢复临时状态，并附加 grid.maximizedNode；应用保存/读取时均移除该标记。实测当前 8px gap 下直接 fromJSON 会有约 5px 宽度漂移：serializeBranchNode 保存可见尺寸，而 Splitview descriptor 恢复后再次扣除 marginShare。只在读取时按可见兄弟数补回间距份额，仍由官方恢复；保存保持官方格式。升级 Dockview 时必须复核此适配，不可直接沿用；几何回归包含正常分组、宽高和连续重启，防止累积偏移。

不保存原生窗口位置/大小；不同窗口尺寸下由 Dockview 按比例和模块最小尺寸适配，不承诺跨显示器像素完全一致。未知模块当前整体回退，不尝试保留部分布局；待模块注册表实际扩展再设计格式迁移。

## ADR-001 公共宿主与独立组件包

- 日期与状态：2026-11-09 用户已接受方案 B；2026-11-10 从既有决定整理为 ADR，不是新增授权。暂无替代项。
- 背景：组件须按需分发、独立启动，并在工作台中停靠/分离；不能继续假定所有业务组件同包发布。
- 备选：A 为自包含应用与接入协议，独立性强但重复携带运行时且跨应用状态交接成本高；B 为公共宿主与独立组件包，共享运行时并集中管理视图；所有组件直接加载在工作台 renderer 不满足独立与权限边界。
- 决定：采用 B，工作台界面可选，组件独立运行仍依赖公共宿主。保留 Electron、React、Vite、Dockview；不用原生任意窗口嵌入替代受控视图方案。
- 后果：降低重复运行时成本，但必须维护宿主/协议兼容、组件权限及独立数据归属；不承诺宿主崩溃时媒体不中断，不把同进程、类型或 iframe 当完整隔离。
- 实现与证据：仅隔离示例原型，当前协议/白名单及测试边界以 [组件开发](组件开发.md) 为准。原生鼠标拖入、音频连续性、正式安装升级与布局迁移尚未全部验收；已接受不等于完整平台已实现。
- 重新评估：视图遮挡/焦点或媒体连续性无法达到验收，或用户要求完全无公共宿主依赖时，先记录证据、提出新 ADR，再决定是否切换 A。
- 关联：[详细架构与验证门槛](组件框架设计.md)、[历史任务证据](任务记录.md)。音乐库、SDK 发布和 monorepo 不在本次授权范围。

## ADR-004 桌面宿主按内置模块管理独立窗口

2026-11-11 已接受。四个内置模块复用工作台的 React 内容，宿主按固定模块 ID 维护独立 BrowserWindow 和内存分区。工作台持有 Dockview 布局写入权，独立窗口只报告自身状态。导航搜索随交接转移，检查器通过受限快照读取活动模块和尺寸。现有外部示例继续使用 WebContentsView。

拖出时先等待独立页面挂载，超时保留来源标签。拖回时由工作台验证实际目标并添加面板，在同一 UI 事件内通过短同步 IPC 兑现一次性令牌、取得最新会话值，失败则撤回面板。同步处理仅检查内存记录和交回窗口，不等待加载、网络或磁盘。这样无需为当前四个可信占位模块增加第三方组件协议。

## ADR-005 组件共享主题与面板材质

2026-11-11 已接受。普通面板作为参照，拒绝在每个组件中复制主题或补偿窗口底色。组件构建时复用 ComponentTheme、设计参数和公共样式，运行时仍可独立部署。主题入口提供 Fluent 控件及配色；面板组与独立页面共享同一材质规则，嵌入的组件页面透出面板组。组件内容保留自己的布局、交互和生命周期。此选择替代示例专用 90% 深色底板，以跨窗口颜色、透明层数及回退测试约束今后的改动。

## ADR-006 第一方音乐会话、存储与来源权限

2026-11-11 已接受。音乐组件复用同一 WebContentsView 和一个 HTMLAudioElement，宿主切换父窗口。工作台持有布局，组件私有服务持有队列、选择和进度。进程重启按已保存位置等待用户播放。

Electron 45.2.3 内置 node:sqlite 实测可打开内存库（SQLite 3.53.4）。采用组件私有单写者；正式录音存放在用户首次选择的目录，数据库保存相对路径、录音身份与哈希。目标卷暂存、校验、独占发布及意图记录负责中断恢复。关应用后分别备份数据库和正式库。

来源按目录、解析、实测音质、临时保存和永久保存分项启用。洛雪 musicUrl 输入已有音乐 ID。只把经确认的偏好字段交给受控模型服务，音频、路径与完整曲库留本机；未知脚本不加载。离线目录与合成录音可独立验收。

## ADR-007 FitBay 独立使用用户导入的音乐源

已确认。用户选择 JS 源后，组件将脚本交给工作线程内的 QuickJS WASM。主进程只接受曲库 ID、主进程签发的候选 ID 和已声明的音质，由系统文件对话框确定源和输出目录。这样可在未安装洛雪的 Windows 设备使用同一音乐组件。兼容范围按实际适配的事件、操作与音源网络能力逐项验证。用户自己的源不随软件分发。此决策扩展 ADR-006 中的源接入范围。

## ADR-008 Music 专用本地 MCP 与多源目录

2026-11-12 用户已指定目录与 Agent 能力。采用 stdio MCP 转接当前用户的 Windows 命名管道，界面和 Agent 均调用宿主单写者的音源业务。旧版当前源原位迁移，内容摘要、仓库来源别名和当前选项持久保存，切换后原有录音与许可规则继续生效。服务只提供目录列表、按已知 ID 导入、能力查询与切换。源运行时沿用 ADR-007。

相比另开进程直接写组件数据库，这一选择保留事务、当前源和在途候选校验的一致性。相比开放通用 IPC 或远程 HTTP，此方案把协议面限定于四种本地业务。代价是使用接口时必须运行与配置匹配的桌面宿主，并需要安全的当前用户目录。当前用户私有 DACL、令牌认证、参数限制及复验记录见[音源目录和本机 Agent](音乐源目录与MCP.md)。

## ADR-009 三个可选的第一方 Music 插件

用户确认将波形、标签封面、智能歌单分别包装并按需安装。每个包包括界面和宿主处理程序，标签包另含独立锁定依赖构建的 TagLib Wasm。构建步骤输出当前三包的 SHA-256 和文件清单。Music 按 profile 安装与登记，通过专用协议加载已安装的界面；宿主按固定插件 ID 和注册的业务操作分派请求。与主程序同等信任的第一方宿主逻辑可按曲目授权调用所需系统能力。此协议面仅覆盖这三项业务。来源可以是构建随附包、用户选择的文件或 HTTPS 直链，均须与当前构建摘要匹配。没有配置公共分发站点。

数据库中的播放标记与智能规则独立于安装文件。卸载清理该插件的安装版本，重装可继续使用已有资料。核心不常听、最近播放、备份和换盘找回可在零插件状态下使用。
