# 技术决策记录

已确认 Electron + React + TypeScript + Vite 桌面方案，布局采用 Dockview。SQLite 和任务执行层属于后续规划，本次不引入。

仅将实际讨论过的重要选择记录在此；候选方案标注为「待讨论」，不得当作已确认决定执行。

## 2026-11-09：总体技术栈候选

- **状态**：已确认第一套方案；基础界面优先落地。
- **背景**：以网页技术实现个人工作台，整合本地创作工具、素材资产与 AI 节点工作流；目前以单人、本机使用为选型假设。
- **首选建议**：Electron + React + TypeScript + Vite + React Flow + Node.js 独立任务进程 + SQLite + 本地文件系统。
- **理由**：桌面主进程可访问本地能力，内置 Chromium 提供一致的界面运行环境；界面和任务调度主要使用 TypeScript，减少初期跨语言维护。代价是浏览器运行时带来的安装体积与资源开销，实际占用需原型测量。
- **候选二**：Tauri 2 + React + TypeScript + Vite + React Flow + Rust 本地层 + SQLite；需要 Python 时接入 sidecar。适合重视安装体积且愿意维护 Rust 的情况；系统 WebView 差异和多语言调试是额外成本，不能保证整个工作台因此更快。
- **候选三**：React + TypeScript + Vite + React Flow 网页前端 + Python/FastAPI 本地服务 + 独立任务进程 + SQLite。适合大量 Python 脚本和算法直接参与执行的情况；需要管理服务启动、通信、访问权限与 Python 环境，若再加桌面外壳也要维护两套运行时。
- **决定**：采用第一套方案；使用 electron-vite 构建桌面主进程与 React 界面，Dockview 开源基础包提供可停靠布局。渲染进程保持沙箱隔离，目前无系统能力调用，因此不设置 preload 接口。

### 视觉与首期范围（已确认）

- 用户选择 Penpot 的 UI 风格，采用其深色工作区的面板层级、紧凑控件与薄荷青强调色；此前 AI 生成概念图已废弃。
- 参考官方截图与公开主题色定义，组件为本项目编写，布局复用 Dockview，图标复用 Lucide；不直接移植 Penpot 的 ClojureScript 应用代码。
- 四个模块仅为占位面板，支持拖拽停靠和尺寸调整；不实现插件、时间线或媒体编辑功能。
- 按完成的功能分别验证和提交 commit。

### 推荐方案的职责边界

- React 组织项目、资产、模块与节点界面；Vite 负责开发和构建。
- Electron 主进程负责窗口、系统交互和进程管理；界面通过受限接口访问本地能力。
- React Flow 负责节点图交互；执行逻辑独立于画布，不能把前端状态当作可靠的任务记录。
- 任务进程负责依赖调度、外部调用、状态记录、失败处理和取消。初期只实现有限的无环流程；持久化中断状态，外部付费任务重试前核查原任务，不能承诺任意步骤自动续跑。
- SQLite 存储项目、资产元数据、工作流版本和运行记录；大素材保留在文件系统，由后台统一管理数据库写入。
- 工具通过 HTTP API、命令行或官方脚本接口接入；需要 Python 库的节点再增加独立 Python 执行进程。
- 插件第一阶段为随应用发布的模块，约定标识、版本、输入输出与执行接口；第三方动态插件及其隔离另行设计。
- 保留业务逻辑与桌面接口之间的边界，方便未来增加浏览器访问，但不承诺零成本迁移。

### 重新评估条件

- 首批核心流程大量依赖 Python 库：重新评估以 Python 为执行核心。
- 实测桌面体积或空闲资源占用不可接受：评估 Tauri，并做同功能原型对比。
- 多人协作、多设备同步成为首期需求：重新评估服务部署、身份认证和数据库方案。
