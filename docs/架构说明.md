# 架构说明

## 新产品目标与当前实现边界

独立安装、独立启动与可停靠组件已是确认目标；下面仍描述当前单体实现，不代表未来所有组件必须同包发布。现有静态模块注册、单窗口退出、v1 未知模块整体回退等假设需按 [组件框架设计](组件框架设计.md) 重新评估。公共宿主方案 B 已确认，决定见 [ADR-001](技术决策.md#adr-001)；详细文档仍含未实现的目标设计，实际原型边界见 [组件开发](组件开发.md)。

桌面 CMD 当前共用 examples/component-host 的主进程和已有工作台页面；下表中的 src/main 是开发及安装包入口。宿主通过专用 preload 接收组件意图和区域边界。

## 当前分层

| 位置                       | 职责                                     | 边界                                                        |
| -------------------------- | ---------------------------------------- | ----------------------------------------------------------- |
| src/main/index.ts          | 窗口、生命周期、导航限制、原生深色背景   | 系统权限仅在主进程；未知输入先校验                          |
| renderer/src/app           | 外壳、Dockview 装配、布局操作            | WorkspaceContext 仅为界面内的布局状态；DockviewApi 不跨进程 |
| renderer/src/modules       | 四个占位模块专属界面                     | 独立文件；通过 app 的布局上下文打开面板/观察尺寸            |
| renderer/src/styles        | tokens.css 集中参数，global.css 应用样式 | 不承担业务逻辑                                              |
| tests、根目录配置、scripts | 实际 Electron 验收、构建、只读环境检查   | 不读取日常 profile 或私人素材                               |

主进程设置原生深色背景，界面直接使用深色 Fluent 参数。正式工作台无需 preload；独立示例宿主仍通过专用 preload 提供停靠操作。

保留 contextIsolation、sandbox，关闭 nodeIntegration；阻止任意导航和新窗口。共享类型不是信任边界：主进程仍需检查 unknown 输入。新增本地能力时按具体用途增加函数、参数与返回类型和运行时校验，限制路径/操作范围；禁止提供 execute(command)、readAnyFile、通用 IPC 等宽泛接口。凭据未来保留在受控主进程或独立执行环境，不下发界面。

当前仅一个窗口与四个占位面板，不引入全局状态库或插件运行时。模块专属代码留在模块文件；只有被多处实际复用时才增加 components。

## 未来边界（未实现）

数据库由本地受控层管理，界面只发用例请求；AI 与媒体长任务不能阻塞 UI/主进程，待首条流程确定后选执行方式；插件 SDK 需要能力权限与生命周期约定，不能直接放开系统调用；外部商业软件优先使用合法 API/脚本或启动入口，不承诺嵌入所有界面。本轮不创建这些目录、数据库或接口。

布局持久化位于 renderer/src/app/layoutStorage.ts：读取并校验版本化 localStorage 后调用 Dockview fromJSON，恢复完成后才订阅布局事件；250ms 合并保存，正常关闭时立即快照。只存界面布局，不新增 IPC 或共享状态库；具体回退与版本适配见技术决策。

桌面宿主的四个内置模块复用 Dockview 面板内容，窗口所有权按模块 ID 管理。独立窗口可以在工作台关闭后运行。窗口与布局交接见 [ADR-004](技术决策.md#adr-004-桌面宿主按内置模块管理独立窗口)。
