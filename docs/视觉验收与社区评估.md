# 视觉验收与社区评估

## 可重复的后台验收

执行 `npm run check`：doctor、格式、lint、2 项诊断回归、类型、一次生产构建、发布/开发各 6 项交互；覆盖主题、最小窗口、拖拽合并/拆分、分隔线宽高调整、模块关闭重开、官方搜索、菜单与弹窗焦点。它不等于帧率或原生材质验收。

执行 `npm run check:visual`：构建后在屏幕外依次启动隔离 profile 的 Electron，使用 Chromium `--force-device-scale-factor` 模拟 1.25/1.5；每个比例检查 1480×960、960×720、900×640 三种窗口的深色玻璃，共 6 组。每组保存工作区、菜单、对话框，共 18 张图；等待动画结束，检查弹层在视口内且中心未被遮挡、Escape 关闭和焦点恢复、页面无横向溢出、窗口未获焦且位于屏幕外。输出在忽略目录 `tmp/visual-check/`，`results.json` 包含实际 DPR、视口与字体证据；失败见终端断言和已生成图片，未生成完整 JSON 时不可认定全部通过。

字体通过 Chromium CDP 获取标题中文实际字形所用字体，并记录 CSS 字号/字重；另外只在测试 DOM 临时去掉首选字体，检查回退后恢复。它不卸载字体、不改 Windows。脚本是简短 JavaScript，受 Biome 检查并实际运行，应用与交互测试仍受 strict TypeScript 检查。

历史双主题样板结果：8 组几何、焦点与背景检查通过；标题为 14px/500，实际使用 HarmonyOS Sans SC。临时移除首选字体后实测回退为 Microsoft YaHei UI；原始记录见 results.json。小窗口允许模块内部滚动，搜索 placeholder 可截短，但标签和输入功能可用。已检查黑白弹窗和小窗口菜单截图；可读性最终由用户在实际显示器确认。

## 社区组件取舍

- [Fluent UI](https://github.com/microsoft/fluentui)：采用 React v9 9.75.1，MIT；已安装包 peer 声明支持本项目 React 19。官方 React 控件工作在 Electron Chromium 中，与 Dockview 同用；本轮实际接入少量样板并验证，无明显兼容阻碍。保留官方键盘与焦点管理，适配现有 tokens；新增依赖和产物体积是需要接受的成本。具体见设计规范、第三方来源。
- [WinUI Gallery](https://github.com/microsoft/WinUI-Gallery)：微软原生 WinUI 3 / Windows App SDK 的 C#/XAML 示例，仓库 [MIT](https://github.com/microsoft/WinUI-Gallery/blob/main/LICENSE)。作为交互和视觉参考；不是 npm React 库，不为接入它新增原生 UI 层。本轮没有复制其资产。
- [Dockview](https://github.com/dockview/dockview)：继续作为布局底座；官方控件只替换面板内容及外壳的少量控件，不接管停靠逻辑。
- [React Flow](https://github.com/xyflow/xyflow)：留到节点图需求明确时评估节点渲染、连线、性能与许可范围；本轮不安装，不提前定义执行引擎。
- [Electron Forge](https://github.com/electron/forge)：留到安装包阶段，届时比较与 electron-vite 的构建衔接、Windows 打包和维护成本；本轮不引入打包、签名、发布或自动更新。

以上远程来源用于选型核查，不代表本项目远程 CI 结果。本轮没有 push；当前提交未运行远程 CI，历史绿灯不能代替。
