# 组件原型开发与验证

状态：方案 B 已确认；这是可丢弃的 UI 生命周期原型，尚非通用第三方组件平台。工作台与 Music 安装版复用公共宿主。

## 桌面工作台双向拖放

桌面 CMD 使用同一公共宿主和原日常 profile。第二次启动只转交“打开组件”或“打开工作台”的意图。组件独立运行时不创建工作台窗口。组件已停靠时，再次从桌面打开Music会选中对应标签；重启工作台自动重连组件时保留原活动标签。安装包与普通开发命令仍有各自的入口。

Music 顶部的「只显示播放栏」保留原播放器；停靠时移除 Music 标签，在工作区底部保留播放栏，独立时缩小原窗口。点击播放栏最右侧的「展开 Music」恢复完整界面。工作区只剩播放栏时，中央显示「可在这里打开其他组件」。「隐藏到后台」释放整个面板或隐藏独立窗口，保留当前播放、暂停、进度和队列。上述三种状态在「窗口 → Music」都显示勾选。完全隐藏时，点 Music 旁的眼睛图标「显示 Music」恢复原来的独立或停靠视图。点击已勾选的 Music 主项会停止并关闭会话，点击未勾选项在工作台中启动。再次从桌面启动 Music 也可显示正在运行的会话。

Windows 原生移动期间，宿主按指针和实际窗口层叠顺序检查可见目标，预览与释放共用落点。中央合并，边缘分屏；已有组件标签也会移动到释放位置。等待目标就绪期间保留交接前的布局快照，超时后组件回到独立窗口。若等待期间布局未被编辑，回退恢复交接前的分组、活动标签和面板尺寸；若已编辑，单独撤回本次标签移动或新增。组件标签在工作台内由 Dockview 处理重排；拖出窗口边界释放后，原 WebContentsView 移入独立窗口。关闭或重启应用后的播放会话持久化另行设计。

开发验证用临时 profile，模拟原生窗口消息并发送网页指针事件；实际 Windows 标题栏连续拖动、跨显示器及混合 DPI 尚待独立桌面验收。下文较早阶段的手柄、双主题和消息验证记录保留为历史证据。

## 构建与验证

在仓库根目录执行：

```powershell
npm ci
npm run build:prototype
npm run check:prototype
npm run check
```

前两项部署命令生成 `dist/component-prototype/host`、`component`、`workbench` 三个独立目录。host 含可信主进程与 preload，component 含清单与独立构建的 Fluent React 界面，workbench 含工作台 renderer。示例在构建时引入公共 ComponentTheme，构建产物自包含；组件协议仍不强制第三方采用 React。均未打包 Electron，当前依赖项目已下载的运行时。无工作台参数时示例可独立使用，但不能省略公共宿主。安装/卸载/升级仍待 P5。

后台启动示例（PowerShell，关闭测试时由测试脚本清理自身进程）：

```powershell
$env:WORKBENCH_TEST_BACKGROUND = '1'
$prototypeRoot = Join-Path (Get-Location) 'dist/component-prototype'
$prototypeProfile = Join-Path (Get-Location) 'tmp/component-manual-profile'
npx --no-install electron "$prototypeRoot/host" "--component=$prototypeRoot/component" "--user-data-dir=$prototypeProfile" "--workbench=$prototypeRoot/workbench/index.html"
```

推荐使用自动脚本，它通过 Playwright 管理关闭，不要求用户操作移出屏幕的窗口。省略 `--workbench` 即验证无需工作台界面的模式；加 `--mode=workbench` 先打开工作台。必须使用独立绝对 profile，禁止指向日常配置。自动脚本每次新建 tmp/profile，输出截图目录；失败时终端给出断言与位置。构建后再运行脚本，避免测试旧产物。

## 最小接入约定

源码见 examples/sample-component/component.json，清单版本 1，协议与 hostApi 均精确匹配 0.1。示例入口只接受 `io.example.counter`、index.html 入口与 `view.transfer` 权限；不支持任意 ID、安装发现目录扫描或版本范围。发现来自显式 `--component` 参数。本轮无新增依赖、SDK 包或 monorepo。

宿主提供冻结的 sampleHost 桥：hello({protocol:'0.1'}) 返回 mode/phase/error/sessionId/theme；transfer('attach'|'detach') 返回 ok/error；subscribe 接收状态并返回取消订阅函数。工作台使用另一套可信桥传递面板 DIP 矩形。仅可信 shell 可控制坐标；组件不能任意 IPC、读取文件或执行命令。主进程核验 sender 与 mainFrame。同一轮接入的重复请求共用结果；成功返回表示宿主已接受请求，实际停靠由 docked 状态确认。错误包括 NOT_INSTALLED、INCOMPATIBLE、DENIED、TIMEOUT、CRASHED。完整请求 ID、协议协商、持久快照迁移留待正式协议实现。

生命周期：宿主加载清单 → 创建隔离 WebContentsView → 独立窗口 → attaching → 工作台面板报告有效矩形 → 移挂同一个视图 → docked；分离反向操作，不重新加载页面。超时保留原窗口；重置/关闭面板分离组件；关闭工作台同样分离。关闭独立组件窗口销毁视图；工作台仍在时可重新打开，所有窗口关闭则退出宿主。BaseWindow 不自动销毁 webContents，原型显式关闭。

队列选择使用 Fluent Dropdown/Option。展开列表与工作台菜单共用半透明底色和背景模糊，当前选项显示蓝色底和勾选。减少透明效果时使用深色实底，Escape 可收起列表。

计数、输入、选择保留在同一个网页内存中，sessionId 是宿主运行标识，不是持久业务会话。整体退出或渲染崩溃丢失这些状态。此示例的计时/队列选择不等于播放器或后台音乐队列。将来音乐播放真源必须脱离可销毁 UI 单独设计、验证。

## 权限、数据及布局边界

示例启用 sandbox/contextIsolation，关闭 Node；使用独立内存 session，拒绝网络、浏览器权限、新窗口与导航，只允许列出的本地资源。可信 preload 属于宿主，组件不能提交自己的 preload。这些是原型防线，不是完整安全沙箱认证；文件符号链接、资源审核、供应链、渲染资源耗尽和宿主崩溃仍需要加固。仅加载仓库内的受控示例，不能用于运行不可信下载包。独立渲染进程崩溃已测试，不代表宿主自身崩溃可隔离。

没有数据库或素材访问。测试输出、profile 在被忽略的 tmp，部署输出在 dist；不读取日常工作区、不扫描私人目录。每 profile 单宿主锁不等于跨 profile 数据单写入保证，正式数据代理尚未实现。

早期隔离原型从默认四模块开始。当前桌面宿主按所选 profile 读写 v1 工作台布局；示例槽仅在专用桥存在时启用。合法空布局会恢复，缺少宿主时只处理示例引用。

## Windows 窗口拖入原型（C03）

现在独立组件的系统标题栏移动会经过 Windows 消息钩子：WM_ENTERSIZEMOVE → WM_MOVING → WM_EXITSIZEMOVE。以窗口标题栏中心（顶部偏移 16 DIP）作为明确的命中锚点；将它移入已打开工作台的模块区域并松开，即请求停靠到现有示例槽或模块 2 分组。暂不按落点选择任意分屏方向。工作台显示“松开窗口标题栏以停靠”提示。仅支持同一公共宿主的示例窗口，不接受任意外部软件。

停靠后拖住顶部“组件拖出手柄”，移出模块工作区再松开会分离；原窗口位置恢复为最近独立窗口位置，尚不跟随释放点。工作区内松开不分离，Esc/指针取消可取消；键盘激活手柄也可分离。原有 Dockview 标签拖拽仍用于内部排列，拖出手柄与标签不是同一个操作。此阶段不承诺整个原生窗口的完整拖动预览。

已验证：脚本向测试专用 HWND 发送原生消息并实际改变窗口位置，经生产消息钩子触发同视图停靠；未命中、取消返回原位、仅进入移动/缩放循环和纯程序移动均不接入。Playwright 发送网页指针 down/move/up 完成拖出分离；不调用分离接口来冒充该手势。继续校验同视图、会话、输入与选择保持，以及后台窗口无焦点。PowerShell 辅助程序只向该测试窗口发送消息，不移动系统鼠标，不改焦点或系统配置。

**仍未验证真实桌面鼠标拖动系统标题栏。** 消息测试不是 Windows 真正的模态移动循环；真实松手时序、Esc、Snap、遮挡、多屏混合 DPI 和跨原生视图指针捕获需人工窗口验收。背景环境无法证明这些效果，P4 只部分验证，不能称原生拖入完整通过。不得为补测试静默接管用户鼠标。

运行仍为 `npm run build:prototype`、`npm run check:prototype`，原生消息检查仅适用于 Windows。截图 [停靠命中提示](images/native-drop-preview.png) 只表示工作台 DOM 提示，不含系统拖动窗口合成。

依据：[Electron BaseWindow 消息钩子](https://www.electronjs.org/docs/latest/api/base-window#winhookwindowmessagemessage-callback-windows)、[微软 WM_EXITSIZEMOVE](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-exitsizemove)。实际使用已安装 Electron 的 hookWindowMessage；未添加 native addon、全局鼠标钩子或新依赖。

## Fluent 样式修正（C05）

示例已改为 React + 官方 Fluent UI Button/Field/Input/Select；图标复用已有 lucide-react。Vite 独立构建，不增加依赖；示例源码纳入 TypeScript 检查。共用工作台主题参数、HarmonyOS Sans SC/微软雅黑回退与固定深色模式，不再使用普通 HTML 表单样式。会话编号移到折叠“连接信息”，计数、选择、输入与切换保持不变。

移除原型默认 File/Edit 菜单，保留系统标题栏用于原生拖动；Win11 支持时启用与正式应用一致的 Acrylic，否则使用普通背景。官方控件的网页材质与系统 Acrylic 分别处理；离屏截图不能验收真实桌面磨砂。Fluent 的运行时样式需要 CSP style-src 允许 unsafe-inline；script-src 仍仅 self，网络/系统权限不放开。

拖出手柄改为 Fluent 按钮与抓手图标，取消、拖出和键盘分离行为保留。新截图覆盖上面的示例图片；重新启动原型才能载入新代码，已打开的旧窗口不会自动刷新或被测试关闭。

## 连贯的原生玻璃背景（C06）

工作台、内置模块独立窗口和示例入口使用同一个 `ComponentTheme`。新 React 组件引入该入口即可获得字体、Fluent 控件、滚动条与材质；弹出列表和菜单使用 `component-popup`。业务样式负责排版与内容。

- 工作台根使用 `surface="workspace"`，面板组绘制玻璃底板。
- 独立文档使用 `surface="window"`，页面绘制与普通面板相同的一层材质。
- 已嵌入面板的独立文档使用 `surface="embedded"`，页面根和 Provider 透明，露出已有的工作台面板。示例移动时沿用同一渲染视图与会话。

Electron 提供原生 Acrylic。网页按共享规则处理实色背景、减少透明效果与系统高对比度。隔离回归对照实际普通面板和输入控件，并检查停靠时的宿主底板和页面透明层。离屏截图用于核对网页绘制，桌面原生合成仍需实机观察。

## 第一方Music

日常工作台从「窗口 → Music」启动或关闭音乐；桌面启动菜单保留 7 号独立入口。示例仅在显式指定示例包的开发宿主中使用。日常启动恢复旧布局时移除其中的示例标签。

`components/music` 独立构建到 `dist/component-prototype/music`。共享宿主为示例和音乐各维护一个视图，音乐 ID 为 io.fitbay.music。只有音乐视图的主框架可调用专用 music preload；工作台仍独占布局写入。独立视图在停靠及分离时移挂，单个 audio 元素持有音源。关闭音乐标签或独立窗口会结束相应播放器，下次打开等待手动续播。

运行 `npm run build:prototype`、`npm run check:music` 和 `npm run check:prototype`。离线目录以稳定录音 ID 生成 16 kHz、16 位单声道 PCM WAV。离线排序使用偏好与本次选中的摘要；每批有一个须选发行版本的曲名和一个目录缺失项。在线推荐和在线版本匹配见下方模型推荐与洛雪音乐源说明。

真实 Windows 验收使用 `scripts/open-workbench.cmd --manual`，先选 1，再用同一个命令选 7。在「本地曲库」选择一首可用录音，点击左侧的播放图标。播放栏固定在窗口底部。在播放期间依次将标题栏拖到工作台四边与中央，观察预览和落点，每次拖标签到工作台外分离，听是否断音或重叠。分离后关闭工作台，确认音乐继续；关闭最后一个音乐窗口后确认安静。再从验收菜单选 7，确认等待手动续播。可一次反馈出现问题的落点、曲名和时刻。

## 本地曲库

首次引导退出后和后续常规启动进入本地曲库。在「设置」添加文件或文件夹。文件可多选，文件夹递归导入。每次选择只授权本次目录或文件，跳过链接；可取消，再次添加可更新标签和发现新歌。导入后台支持 MP3、FLAC、WAV 和 M4A。按歌名、艺人或专辑搜索，点左侧播放，播放队列取点击时可用的结果。缺失歌曲可重新定位。垃圾桶默认仅移除 FitBay 条目与歌单引用；选择同时删除文件后需核对完整路径并确认，系统回收站操作失败时保留条目。

曲库侧栏按导入根和包含音乐的子目录浏览。旧索引没有记录当时选择的根，以现有曲目所在目录恢复可推断的层级。「我的歌单」旁点加号新建，再点歌曲右侧的歌单图标勾选。每首歌可加入多个歌单。点「多选」可逐首勾选或全选当前搜索结果，再点「加入歌单」指定目标。自建歌单与「歌曲推荐」可批量「从当前歌单移除」，曲库、其他歌单与原文件均保留。打开或刷新「歌曲推荐」会自动移出已确认文件被删除的成员，暂时离线的磁盘保留记录。右键文件夹可移除分类，歌单中的引用仍可播放。右键自建歌单可重命名或删除。双击歌曲文字或行内空白处可播放。窄窗口点「曲库导航」展开侧栏。

底部播放器的「上一首」「下一首」沿当前队列切歌。默认顺序播放，点模式按钮可以切到随机播放。当前歌曲继续播放，队列中的歌曲每轮各播一次，末首结束后停止。随机模式下「上一首」按已播放顺序回退；切回顺序播放后恢复原队列次序。四个页面和停靠、分离窗口共用播放器。再次点当前歌曲的播放键可以暂停或从原进度继续。

本地音频通过音乐隔离 session 的专用协议按范围读取，渲染器只持临时音源令牌。长歌进度、队列和推荐页共享同一个播放器。测试素材位于 tests/fixtures/local-music，源自 330 Hz 合成正弦信号；长 WAV 在隔离测试目录生成。`npm run check:music` 包含旧库迁移、本地格式和长录音专项。

## 最近播放与曲库资料

「本地曲库 → 最近播放」按每首歌最后一次有效收听的日期分组和倒序展示，重复收听计数继续累计；从曲库移除或已确认文件删除的歌曲退出最近播放。有效播放与「不常听」共用同一入口，旧版已有上次收听时间的曲目只补入那一次已知记录。歌曲行的「管理歌单」可勾选「我的收藏」。

「设置 → 本地曲库 → 曲库管理」导出 JSON 资料，包括歌单及曲目顺序、推荐歌单、智能歌单规则、收藏、有效播放历史、推荐草稿、负反馈和偏好文档。音频需另行备份。恢复先预览再合并；新曲目在首次重新定位前显示离线。原位置或新磁盘都可通过「选择新目录」匹配，同名候选需手选，未找到的引用保留。现有模型凭据和授权留在原 profile。独立静音复验使用 `node scripts/check-music-library-tools.mjs`。

## 洛雪音乐源

「下载音乐」优先用当前源取址。源无法提供所选录音或返回的音频下载、解码失败时，会按导入顺序尝试支持相同平台与所选音质的备用源。完成后可在下载页看到实际尝试顺序。仅本次下载使用备用源，设置中的当前源和后续搜索仍沿用原选择。遇到同名文件或用户取消时直接停止。

「下载音乐」分网易云音乐、QQ 音乐、酷狗音乐三个标签。切换平台会沿用已填的歌名和艺人，重新查询所选平台。当前源缺少该平台搜索或取址能力时，页面提示更换音乐源。

在「设置 → 音乐源 → 本地导入」选择 JS 文件，也可以点「在线导入」，粘贴公网 HTTP(S) 脚本直链并点「导入链接」。通过校验后可使用新源，已导入的源保留在「当前音乐源」列表里。「音源目录」支持勾选多项，已有活动源时保留选择；本机代理的接入方法见[音乐源目录与 MCP](音乐源目录与MCP.md)。到「下载音乐」手填歌名、艺人或两者，或在「从曲库选择」中按歌名、艺人筛选并选一首已有歌曲，点「查找版本」，在最多 50 个去重版本中按歌名、艺人和专辑核对结果，选音质后点「下载」，文件保存到设置中的手动下载目录；尚未设置时弹出目录选择框。已存在的文件会保留。源的取址结果及音质取决于上游，实际格式由文件内容检测。

适配桌面协议的 inited、request、musicUrl、公网 HTTP(S) 请求和定时器。优先使用源自带的 search 操作；网易云、QQ、酷狗仅声明 musicUrl 时由 FitBay 搜索对应平台目录，然后把所选版本与音质交给当前源取址。QQ 保留歌曲 MID 和媒体 MID，酷狗保留录音及各音质文件哈希。旧源升级后保留原来的活动源与默认平台。依赖完整洛雪工具集、订阅管理或自定义登录的源尚未适配。无需安装洛雪，也无需启动本地 HTTP 服务。测试入口为 npm run check:lx。

专项检查需先构建桌面宿主。默认 npm run check:lx 在独立 profile 中使用自制源和测试音频。真实联调可设置 FITBAY_LX_TEST_SOURCE 为自己选择的 JS 文件、FITBAY_LX_TEST_TITLE 为已导入的歌名，运行 node scripts/check-lx-music.mjs --live。该模式只读日常索引中的一条匹配记录，下载结果放在本次临时目录。

音乐视图的专用接口位于 window.music。lxInfo 和 lxImport 分别读取当前源名称、通过文件对话框导入源；lxSearch 接收曲库或推荐记录 ID，也支持手填的歌名与艺人，返回候选 ID 和音质；lxDownload 接收候选 ID 和音质，使用手动下载目录或弹出目录选择框完成下载；lxCancel 取消当前源操作。候选 ID 在重新搜索、换源或关闭组件后失效。

## 模型推荐

在「Music → 设置」选择 DeepSeek、OpenAI、Claude 或 Gemini，保存模型 ID 和密钥，分别指定手动与推荐下载目录。可以选同一个目录。首次在「每日推荐」点击在线生成时，若尚未设置推荐下载目录，会先打开系统文件夹选择窗口。选定后立即保存路径并继续本次生成，重启后沿用，可在设置里更换。取消会保留输入，本次生成随即结束。首选音质在源支持时使用。切到「每日推荐」，可用自己的话描述风格、场景或指定歌手；留空时使用已有偏好。

「本次推荐」展示本批成功入库的新歌。生成前可设置目标首数，默认为五首。「已下载」显示实际入库数与目标数，点击「播放本次推荐」会按展示顺序播放当前已下载的歌曲，余下歌曲继续处理。跨日清理旧批次及临时结果，为以后去重保留歌名与艺人，下载文件、曲库、歌单及显式反馈继续保留。

推荐结合已授权的审美资料和本次输入，逐首核对歌名与艺人、匹配录音和下载。自动保存来源明确允许永久保存的完整录音，排除已有及历史推荐，跳过失败候选并继续补推。风格推荐优先不同艺人。运行中可点击「终止本次推荐」停止检索、补推和传输，清理未完成文件，连续六轮没有新增录音或连续三轮只有已排除候选时停止继续请求；下载或模型遇到整批阻塞时显示原因，已入库歌曲保留。可在批次详情核对检索和取址失败。已就绪的曲目可从曲库本地播放。

保存推荐前，Music 核对临时文件和曲库中的实际录音。文件字节相同时用 SHA-256 判重。改标签或重新编码的文件由随附的 Chromium 解码器比较波形、全曲频段能量和时间对齐。短于四秒的录音比较解码后各声道的 PCM 摘要。单文件超过 128 MiB 或时长超过 20 分钟时保留字节级核对，以控制后台解码内存。相似度不足的版本保留，确认相同的录音退出本批，原文件及其歌单继续保留。

在设置里一次授权发送歌名、艺人、专辑及主动加入自建歌单的偏好信号后，推荐会读取组件私有的审美文档。只在有新增信息时更新；失败保留旧资料和未处理的增量，可撤回授权。自动下载本身不计作喜欢。密钥由 Electron safeStorage 加密保存，渲染界面只能读取配置状态。受控模型协议和音源回归运行 `npm run check:models`。

在「全局快捷键」启用媒体键，或为播放／暂停、上一首、下一首设置自定义组合。系统占用时设置页显示反馈。关闭最后一个 Music 窗口后释放注册。

### 音量、歌词和曲库整理

播放栏的扬声器按钮只控制 Music 音量，解除静音会恢复原音量。点「词」可打开置顶桌面歌词，再次点击关闭。音乐文件旁的同名 LRC 优先使用；源提供同步歌词时，手动下载与每日推荐均会保存配套文件。在「本地曲库 → 不常听」可按 30、90 或 180 天筛选，有足够观察历史的曲目才会出现，固定按最久未听优先排列。在该列表试听、多选后，可查看合计容量并选择移除方式。

### 使用引导和延期功能

Music 各主页面的顶部导航右侧提供圆圈问号「使用引导」，位于收起及隐藏按钮之前。四步依次定位音乐源、MCP 连接方法、模型设置和推荐输入框；完成或跳过后回到进入引导前的页面。波形与片段试听、标签与封面整理、智能歌单延期，既有用户资料保留。

### 音乐组件的玻璃底衬

音乐组件使用独立 WebContentsView，加载时先显示宿主深色底板，页面就绪后切换为透明合成。独立窗口沿用公共面板材质，停靠时直接透出工作台底板。服务商和下载音质选项使用公共 Fluent 弹层，减少透明效果及强制颜色模式使用对应主题回退。
