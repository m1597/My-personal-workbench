# Music 音源目录和本机 Agent

全新 Music 首次打开即在后台检查内置目录。首个通过隔离运行时能力检查的音源即可用于普通找歌，其他可用音源陆续加入。断网时保留进度，联网后自动重试。完成首轮后重启复用已有清单；初始化固定失败的脚本按内容版本记住，之后目录更新时可重新验证。

每次开始推荐时，Music 检查上游目录、健康报告和脚本版本，自动导入通过能力检查的目录源。上游明确停用、删除或脚本确证损坏的目录源会退出候选；同一源如果也由用户手动导入，会保留记录并标注停用。下次检查发现恢复后重新验证。仓库暂时不可达时使用已有可用源。单首取址失败、网络超时和上游「异常」状态不会触发永久停用。

已有独立手动源时，推荐会并行启动仓库检查和手动源匹配。需要目录源补选时，或本轮完成前，Music 自动完成脚本更新。目录管理的源必须先通过本轮检查。推荐优先保存音频，再补齐歌词。

手动下载沿用所选平台、录音和音质。首选源响应较慢时，Music 同时向另一已导入且支持该音质的源取址，只传输其中一个结果。

打开 Music → 设置 → 音乐源 → 音源目录，勾选需要的条目后点「导入所选」。第一次打开可用内置目录，点「刷新目录」读取上游 README。每项分别报告结果，已有当前源时保留当前选择。首次成功导入后可直接使用。下拉「当前音乐源」可切换回先前导入的源。本地文件及在线直链继续支持。

仓库条目按目录 ID 合并原始与加速链接，并以脚本内容摘要识别已从本地导入的副本。刷新目录只取索引。下载脚本时优先 GitHub 原始地址，失败后尝试 GitHub Contents API 和上游列出的 gh-proxy.org 镜像。镜像可提供与 GitHub 不同的字节，导入后仍经过同一个隔离运行时。上游源会变更或失效，平台目录检索和脚本的取址操作可分别成功或失败。[上游目录](https://github.com/pdone/lx-music-source)

## 可选的外部 Agent 连接

在 Music 的设置中选择 MCP，打开「允许本机 Agent 连接 Music」。检测到一个支持的客户端时直接写入，多个时先选择 Codex 或 Claude Desktop。重启所选客户端并保持 Music 运行，设置页收到真实 MCP 初始化后的心跳才显示「已连接」。关闭开关移除 FitBay 写入且尚未被用户修改的条目；同名的既有条目和其他服务保留。Codex 通过官方 CLI 更新配置，Claude Desktop 使用其 stdio 配置文件。[Codex MCP](https://developers.openai.com/learn/docs-mcp/) · [Claude Desktop 配置](https://py.sdk.modelcontextprotocol.io/get-started/real-host/)

可以直接在 Agent 的对话里提出以下任务。

- 从最近播放的录音里找到上一首，加到指定歌单。使用 `recent_tracks`、`list_playlists` 和 `add_to_playlist`。
- 结合当前对话里的视频脚本，使用 `search_library` 浏览或搜索可用本地录音，由 Agent 按镜头选择排序，用 `create_listening_playlist` 新建试听歌单。
- 通过 `compare_playlists` 比较两个歌单，包含共有的在线引用。按相同录音 ID 匹配，保留第一个歌单内的顺序。

列表工具传入从 0 开始的 `offset`，每次最多返回 50 项。曲库工具只传录音资料和 ID，以上任务无需授权文件夹。专项命令 `node scripts/check-music-mcp-settings.mjs` 使用独立客户端配置和测试曲库。

### 手动接入

本仓库已为 Codex 配置项目级 `fitbay_music`。从该工作区新开 Codex 会话并打开 FitBay 后，即可让 Agent 列出自己的已装音源、检查能力或切换。运行 `codex mcp get fitbay_music` 可以查看该项目实际加载的配置。其他 stdio 客户端可使用下面的配置。

已在本机 Codex app-server 直接调用四项 MCP 工具。独立 Music 窗口先导入 Fish，再多选 Fish 与 Huibq，保留当前选择并得到两项。切换到 Huibq 再切回 Fish，尝试无效目录项后两项仍在。关闭宿主及客户端、用同一测试 profile 重启后，已装清单和选中源一致。回归命令为 `node scripts/check-music-agent.mjs`，需要 Codex 客户端、已构建的桌面入口和可访问的上游目录。

先用桌面入口打开 FitBay 或 Music。把以下服务器配置放入支持标准 stdio 的本机 Agent 的项目级配置。本仓库没有改动全局 MCP 配置。当前机器的启动命令如下。

```powershell
& 'D:\nodejs\node.exe' 'D:\Desktop\个人工作台开发\scripts\music-source-mcp.mjs'
```

```json
{
  "mcpServers": {
    "fitbay-music-sources": {
      "command": "D:\\nodejs\\node.exe",
      "args": ["D:\\Desktop\\个人工作台开发\\scripts\\music-source-mcp.mjs"]
    }
  }
}
```

源码入口默认连接本仓库的 `local/desktop-profile`。在 Music 的「设置 → MCP」可以复制本机启动命令，首次使用引导的最后一步会打开此页。安装版的脚本位于 Music 安装目录的 `resources/app/scripts/music-source-mcp.mjs`，默认连接 `%APPDATA%/FitBay/desktop-profile`。验证专用宿主时在 args 末尾加上宿主已打开的绝对 profile 路径。标准输入输出只承载 MCP JSON-RPC。[stdio 规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)

| 工具                  | 参数示例                               | 返回                                               |
| --------------------- | -------------------------------------- | -------------------------------------------------- |
| `list_sources`        | `{}`                                   | 仓库目录、已安装源和当前 ID                        |
| `import_sources`      | `{"ids":["fish"]}`                     | 每个选中目录 ID 的结果或失败原因                   |
| `source_capabilities` | 使用上一项返回的 `{"id":"pdone:fish"}` | 已接入平台、检索方式、取址操作、音质、永久保存声明 |
| `select_source`       | 使用实际返回的源 ID                    | 切换后的能力                                       |

本地导入或从旧版迁移的源可能使用 `sha256:` ID。显示名不唯一，应始终传入实际取得的 ID。声明的音质和取址操作只描述接口。曲目是否可下载、是否能解码、是否有永久保存许可要分别确认。永久保存为 `null` 表示源没有声明，推荐自动下载继续执行原有的逐曲授权校验。

## 权限审核和验证

服务与当前 Windows 用户绑定。宿主在系统 LocalApplicationData 下原子创建仅当前用户有权限的 FitBayMusicAgent 目录，按 profile 的实际路径摘要分开描述符。启动和连接检查父目录写权限、重解析点、DACL 和所有者，验证失败时关闭该接口。每次启动生成随机命名管道和 256 位令牌。本机同一用户进程是信任边界；同一用户运行的不可信软件可使用该接口。客户端根据固定的音源与曲库工具清单校验参数，宿主独立再次校验。Agent 只能按目录 ID 导入，无法提供脚本内容、网页链接、文件路径或 IPC 名称。脚本照旧在工作线程中的 QuickJS WASM 加载，网络访问沿用既有公网与资源限制。

运行 `node scripts/check-music-sources.mjs` 复验旧源迁移、内容与 origin 去重、升级、不同源切换、部分失败、权限状态、错误令牌与异常 DACL 拒绝。测试会把独立 profile 的描述符临时授予内置 Users 读取权，验证连接被拒后删除。2026-11-12 实测专属目录关闭继承，唯一允许项为当前用户 FullControl；该用户及管理员仍应按正常系统安全方式保护主机。

真实来源专项使用独立 profile、后台静音宿主和官方 MCP SDK 客户端。需要现场复验时可把官方 SDK 安装在临时测试目录，项目生产依赖保持原样。

```powershell
npm run build:prototype
npm install --prefix tmp/mcp-sdk --ignore-scripts --no-audit --no-fund @modelcontextprotocol/sdk@1.32.2
$env:FITBAY_TEST_SDK_DIR = (Resolve-Path tmp/mcp-sdk).Path
node scripts/check-music-source-live.mjs fish
```

## 下载性能复验

构建后运行 `node scripts/check-source-speed.mjs`。传入另一个构建的宿主路径可在相同的两组音源、曲目、音质、模拟网络延迟和独立数据库上对照。计时以毫秒为单位；首字节从该音频请求开始计算，传输从首字节到正文结束，入库时间从点击生成的等效 IPC 调用起算。

| 受控录音，共一首手动和五首推荐 |        改前 |       改后 |
| ------------------------------ | ----------: | ---------: |
| 手动刷新目录                   |         120 |        136 |
| 推荐前仓库网络                 |           0 |        252 |
| 手动搜索 / 成功取址            |   65 / 1867 |    60 / 94 |
| 手动首字节 / 传输              |     78 / 45 |    76 / 44 |
| 手动下载入库                   |        2378 |        639 |
| 推荐首首 / 五首入库            | 1032 / 1959 | 948 / 1850 |

两次均成功入库全部六首。受控源之一延迟取址约 1.8 秒，另一源延迟约 40 毫秒；实际歌曲的网络吞吐和可下载率需单独测量。

公网复验使用相同的五个 Samplelib 公开 MP3、同一个返回固定候选的测试模型和全新隔离目录。首次发现回退时，首首和第五首分别耗时 12.48 秒和 30.01 秒；分段复现为 20.26 秒和 32.03 秒。调整后两轮分别为 2.68 / 4.13 秒、3.04 / 3.38 秒，均五首入库。第二轮在 6.35 秒完成全部工作，源清单含原手动源和 14 个自动导入源。公网耗时随链路波动。

在最终集成构建，点击生成至第一首可播为 3.10 秒，第五首入库为 4.27 秒，目录检查与歌词任务在 7.36 秒内完成。相同五首在引入仓库巡检前为 3.44 / 7.25 秒。逐文件核对 SHA-256 一致，均为 128 kbps。样本使用固定模型响应，端到端时间不含真实模型服务排队。

另取其中一首 307,453 字节的录音，用本机洛雪 2.12.6 自带的下载引擎和 FitBay 交错各请求两次。重定向优化前，FitBay 总耗时 3.57 / 2.54 秒，洛雪 1.82 / 1.66 秒；优化后 FitBay 为 2.50 / 2.65 秒，洛雪为 2.79 / 2.26 秒。两个引擎的输出摘要相同。此项比较仅覆盖取到相同 URL 后的下载，未测洛雪图形界面的搜索或模型推荐。

2026-11-13 按日常五首实测。复制当前 DeepSeek 与 fish_music 配置到隔离曲库，用真实生成按钮、独立推荐目录和 Chromium 离线解码核对五个不同录音。一次基线首首 15.02 秒、第五首 57.41 秒，六轮模型请求。补推时为剩余名额最多多取两个备选，单轮仍至多五首，匹配与落盘名额按目标限制。遇到坏候选可以直接续用备选，受控回归中首轮两首不可用、补推第一首也不可用，两次模型请求仍完成五首。相同目标、候选、模拟源和慢传条件下，旧策略在该阶段只入库两首，新策略已有四首可播，随后第五首完成。

改动后在线实测首首 15.23 秒、第五首 121.43 秒，七轮模型请求，五首全部解码。两轮随机候选和源端响应不同，在线样本未观察到整体提速。固定模型与五个相同公网 MP3 单独复验为 3.10 / 6.64 秒，包含目录与歌词后台收尾共 10.56 秒。验收断言以实际保存录音的歌名核对界面，允许同一推荐选中带版本后缀的录音。

## 在线歌单换源

歌单保留最初选择的录音和位置。原源无法取址或媒体请求失败时，Music 会尝试已导入的其他来源。平台目录来源可以复用同一平台的录音标识。对自定义搜索结果，需核对歌名、艺人、版本以及平台录音 ID 和时长，或核对同一 ISRC。其他版本供手动选择。失败提示保留在播放器，连续播放可跳至下一首。

在「设置 → 音乐源 → 音源目录 → 播放备用目录」添加公网清单 URL。清单格式为 `{"sources":[{"url":"./source.js"}],"repositories":["https://example.org/more.json"]}`。已安装来源全败时，同一播放队列共享一次目录刷新，新增或更新且通过原沙箱能力检查的脚本随后参与重试。清单列出的其他目录需手动选择「使用此目录」才会纳入刷新。单曲播放失败不影响该源对其他录音的可用性。

专项 `scripts/check-playlist-recovery.mjs` 使用独立桌面静音播放四条在线引用，检查 403、备用同录音、一次共享刷新、版本选择、续播、原次序以及未授权目录零请求。公网专项 `scripts/check-playlist-recovery-live.mjs` 读取变量 `FITBAY_TEST_LIVE_LIBRARY` 指定的首开测试数据库，从中复制已导入的公开源到新 profile；可设置 `FITBAY_PLAYBACK_PLATFORM=tx` 走 QQ 真实搜索。原源故障由夹具注入，其余源与媒体请求访问公网。

## 曲目行操作

曲库和歌单仍可单击曲名播放，歌曲保留本地、在线或缺失标识。已有本地文件的拖出手柄位于行尾，可以将单个文件或多选的文件拖到其他应用。「全部歌曲」右侧的「最近入库」与「多选」相邻。

在线找歌的结果和歌手代表作均可双击行播放，键盘可聚焦行并按 Enter。行尾提供下载与加入歌单；右键菜单提供播放、下载、加入歌单。下载和添加歌单各自独立于播放。

2026-11-14 私有桌面专项 `check-music-online-search.mjs`、`check-music-release-catalog.mjs` 验证同一界面播放、下载与歌单成员变更；`check-library-row-layout.mjs` 在宽 920 和 410 的窗口验证布局、曲库单击和可拖出手柄。用两个选中录音重新投放至 Blender VSE 并打开保存的工程，均为 SOUND 素材，片段长度分别为 288 和 168 帧。
