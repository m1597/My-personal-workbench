# FitBay Music 音乐体验候选 · 第四轮

## 把旧播放器的歌单带进 FitBay

换播放器时，最想带走的往往是自己排好的曲序。FitBay 已经能导出 M3U8，建议先补上导入。选择一个 UTF-8 的 M3U 或 M3U8 文件后，以歌单所在目录解析相对路径，按原顺序匹配已入库的本地文件。预览分别列出可导入、未匹配和重复的条目；确认后新建歌单，同一曲目取首次出现的位置。可先用 FitBay 自己导出的歌单往返验证，再试 Strawberry 生成的相对路径歌单。[Strawberry 的 M3U 解析器](https://github.com/strawberrymusicplayer/strawberry/blob/master/src/playlistparsers/m3uparser.cpp) · [FitBay 现有导出](../examples/component-host/library-tools.mjs) · [歌单成员与顺序](../components/music/local-library.mjs)

## 从一段喜欢的演奏找到参与者

听到一段贝斯，想知道是谁弹的，可以在歌曲详情里展开「参与人员」。Picard 定义了按乐器区分的演奏者和制作人等标签。FitBay 可先读取本地文件里明确写出的角色与姓名，例如「贝斯 · 某某」，点姓名再看曲库里有同名署名的其他录音。首版可先支持 FLAC 和 MP3，用同一首歌分别验证多位演奏者、多人兼任角色以及缺少署名的情况。同名者先保留原始署名，避免误合并。[Picard 标签映射](https://picard-docs.musicbrainz.org/en/latest/appendices/tag_mapping.html) · [FitBay 现有专辑标签读取](../components/music/albums.mjs)

## 让工作素材歌单退出推荐偏好

搜集十几首配乐做视频，容易让下一轮个人推荐也围着这批素材转。Spotify 允许减弱某个歌单对推荐的影响，同曲从其他入口播放仍可计入。FitBay 当前用入库、加入自建歌单和主动收藏作为偏好信号。建议让用户将素材文件夹或歌单标成「不用来推断我的喜好」，过滤来自该入口的样本，保留用户主动收藏或加入其他偏好歌单的信号。一个文件已从普通曲库入库时，仅排除歌单仍会留下入库信号，界面应说明范围。旧样本已经进入偏好摘要时需要重新计算。[Spotify 官方说明](https://support.spotify.com/pw/article/exclude-playlists-or-tracks-from-your-taste-profile/) · [FitBay 偏好采样](../examples/component-host/music-taste.mjs)

## 听到翻唱时找同一作品的其他演绎

在一首翻唱的播放页点「其他演绎」，看看哪些人也录过这首作品，再挑一个版本试听。MusicBrainz 通过作品与录音的演出关系把多个演绎关联起来。FitBay 可先为已经确认 MusicBrainz 录音标识的曲目查询作品，再列出关联录音的表演者和标题。只有找到可播放来源的条目才给试听按钮；同名但没有作品关联的歌曲不并入结果。一首串烧可能关联多部作品，此时先让听众选要探索的作品。[MusicBrainz 作品与录音关系](https://musicbrainz.org/doc/How_to_Use_Works) · [FitBay 发行目录查询](../examples/component-host/release-catalog.mjs)

## 按空闲时间排歌

在歌单的播放菜单输入 25 分钟，从当前列表挑出总时长接近目标的完整歌曲，并显示实际时长。本地曲长就足以计算。The Run List 已提供按跑步时间组织播放列表的交互。[The Run List](https://therunlist.app/)

## 插件候选：从一首歌过渡到另一首

用户指定起点与终点，插件根据本地音频特征挑选中间曲目，让风格逐步变化。初次音频分析有额外开销，适合按需安装。AudioMuse-AI 的 Song Path 公开了沿特征空间选择过渡曲的实现思路。[AudioMuse-AI 算法说明](https://github.com/NeptuneHub/AudioMuse-AI/blob/main/docs/ALGORITHM.md)
