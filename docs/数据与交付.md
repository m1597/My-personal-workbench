# 数据与交付

## 存放边界

| 内容                       | 当前位置或约定                                                                                  | Git 与备份                                               |
| -------------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 源码、配置、文档与选定截图 | src、tests、scripts、docs、根配置                                                               | 提交后由 Git 记录，未 push 的 commit 仍只在本机          |
| 随应用发布的静态资源       | src/renderer/public                                                                             | 仅放可分发资源，不放私人素材或字体文件                   |
| 用户原始素材               | 原有外部素材库，或未来根目录 data/                                                              | 不移动现有素材，data/ 已忽略，单独备份                   |
| 应用设置                   | Electron app.getPath('userData') 内的 profile；Windows 默认基于 %APPDATA% 和应用名              | 当前布局在该 profile 的 localStorage，不受仓库 Git 保护  |
| 浏览器预览设置             | 浏览器对应 localhost origin 的 localStorage                                                     | 与 Electron 设置独立，清理浏览器数据会丢失               |
| 未来运行数据与日志         | 根 local/，日志可用 local/logs/，具体功能落地时再确定                                           | 已忽略，没有当前日志或数据库实现，不建空目录             |
| 缓存                       | Electron profile 缓存、npm/Electron 自身缓存；项目 tmp/、.cache/                                | 可再生成，通常无需备份，不擅自改工具全局缓存目录         |
| 测试输出                   | test-results/production、development 的隔离 profile、trace、截图；playwright-report/；tmp/ 截图 | 已忽略，不上传 profile；报告可能含测试快照，只用合成数据 |
| 构建与依赖                 | out/、node_modules/                                                                             | 已忽略，可由锁文件与源码重建                             |
| 备份                       | 根 backups/ 或独立磁盘/备份位置                                                                 | 已忽略，不把与原件同盘的副本作为唯一保障                 |

设置路径由 Electron 管理，不为了目录整齐搬动现有 profile。关闭应用后再备份需要保留的 profile 与素材，恢复前保留当前副本并核对版本。Git 不保存被忽略内容、外部文件和未提交修改；本地 commit 不等于远端或异地备份。本轮没有移动、删除或导入个人文件。

未来凭据只在受控主进程或执行环境读取，不写进 React bundle、shared、Git 或日志。目前无凭据需求，不添加假模板。以后确需 .env.example 时只写变量名与非真实示例；忽略规则不能撤回已跟踪的秘密。

## 依赖维护

1. 开任务记录，说明更新对象与原因；查上游变更、维护状态、引擎要求和许可证。
2. 在可回退提交基础上，一次更新一组相关依赖。用明确版本，例如 `npm install --save-exact 包名@版本`，开发工具加 `--save-dev`；同时提交 package.json 和锁文件。
3. 执行 `npm ci`、`npm run check`，UI 相关更新核对深色截图。审阅 npm audit 和锁文件差异，不自动强制修复全部依赖。
4. 同步来源、环境基线、决策与任务记录，独立提交；主版本升级不与业务变动混合。

## 版本、未来安装包与回退

当前 0.1.0 为开发版本，不代表已经发布。准备可交付版本时明确验收范围，更新 package.json 与锁文件版本、变更说明和兼容性；通过验收后提交，再按用户确认的发布计划创建带说明的 vX.Y.Z tag。日常功能不必每次打标签，push 与发布分别授权。

首次分发时再选择打包工具，汇总实际运行依赖及完整第三方 notices（包括 Chromium、Node 和图标许可），核查字体和静态资源分发权；验证干净机器安装、启动、卸载和旧数据兼容。签名、自动更新、云端发布均未实现，本轮不引入相关服务或凭据。

代码回退优先 `git revert` 对应提交，保留历史，重新 `npm ci` 和 `npm run check`；不得通过破坏性操作清除用户成果。软件回退使用上一已验收版本，先备份设置和素材；未来数据库迁移要另设计恢复方案，不能假定降级代码自动回滚数据。

## 布局数据

键为 `workbench.layout`，值为 `{ version: 1, layout: Dockview序列化结果 }`。使用 Electron profile 的 localStorage（Windows 默认 `%APPDATA%/personal-workbench/Local Storage/leveldb/`，实际以 app.getPath('userData') 为准）；不在仓库内存放 JSON 文件，不由 Git 备份。浏览器预览、开发服务器 origin 与构建版 file origin 的存储相互独立，不自动迁移。更改应用名、profile 或开发端口可能使用新的设置空间。

正常关闭会同步更新 localStorage；强制结束进程、断电、磁盘不可写或清理 profile 不保证保留最新修改。存储异常仅警告，不阻断工作区。缺失、损坏、不支持版本、未知模块或不支持的浮动/弹出布局整体回退默认四模块，并在恢复完成后保存有效默认值；本轮不做部分迁移或坏数据备份。已登记示例的组件槽独立校验；无宿主或组件不可用时仅移除该槽。合法空布局不会触发回退。需要保留设置时，在关闭应用后独立备份 profile，不直接编辑 Chromium LevelDB 文件。

## 首个本地试用安装包（0.1.0）

使用 electron-builder 26.18.0 + NSIS，只生成 Windows x64 安装向导；保留 electron-vite 构建。Forge 的常用 Squirrel 方案不适合本次自由选安装目录的需求，未同时引入两套工具。官方配置依据：[NSIS](https://www.electron.build/nsis/)、[Forge Squirrel](https://www.electronforge.io/config/makers/squirrel.windows)。

步骤：npm ci → npm run check → npm run dist:win → npm run check:package。dist:win 使用已经下载的 Electron，准备固定 .cache/package-app 暂存目录，仅复制 out、精简元数据、项目 LICENSE 和第三方 notices；files 显式排除 node_modules，现有界面依赖已经打进 renderer。未来主进程新增外部运行依赖时必须调整暂存策略，不能沿用无依赖假设。暂存和 dist 均被忽略。初次构建 NSIS/7zip 需要网络；不修改全局安装或云权限。

交付文件为 dist/FitBay-Setup-0.1.0-x64.exe；支持当前用户安装、选择 D 盘目录、桌面/开始菜单快捷方式，完成后不自动运行。不自动安装到本机，不强制管理员提权。卸载通过 Windows“已安装的应用”，配置保留；重装/回退前关闭程序并备份 profile。内部包名和可执行文件名沿用 personal-workbench，产品名、系统标题栏和安装快捷方式显示 FitBay。本次未验证安装向导/卸载、干净 Windows 机器或旧安装覆盖升级；后台 check:package 验证的是实际打包目录中的 exe，不将其称作安装验收。

包未签名，Windows 可能显示未知发布者或信誉提示；没有证书、自动发布、更新服务或下载执行逻辑。0.1.0 仅本地试用，不创建远程 Release/tag，不 push。正式分发前补签名、真实安装卸载/升级验证及更广泛系统兼容验收。

依赖审计：运行依赖 npm audit --omit=dev 为 0；新增打包工具依赖链存在 6 个 moderate 报告，根因为 minimatch 模式放大 DoS（GHSA-g3hv-75wg-m249）。仅用于本机固定受控 glob 的构建，不随 app.asar 分发；未使用 audit fix --force 降级或跨主版本替换。后续跟进上游修复，不能宣称全依赖无漏洞。

## 组件化后的交付边界（提案）

上述 0.1.0 包与布局 v1 是当前事实。未来独立组件不能默认随工作台 out 一起打包；工作台/组件卸载均不得默认删除素材。推荐的公共宿主、组件登记、单写者和数据分区尚未实施，见 [组件框架设计](组件框架设计.md)，等待用户确认。v1 未知模块整体回退只适用于当前固定四模块，未来缺失组件应保留布局占位，不抹掉其他面板。

## 音乐试听

音乐首次打开时创建 `<profile>/fitbay-music/music.sqlite` 和同级 `audition-cache`。数据库保存偏好、按日分组的批次、理由、目录版本 ID、勾选、队列和进度。缓存使用组件生成的 UUID 命名，按使用时间清理。正式 WAV 保存到首次批量保留时用系统对话框选定的目录。路径映射、SHA-256、发行版本和入库意图在私有数据库中。目标卷临时文件写完、校验后，由 Windows MoveFileW 独占改名，崩溃后按日志恢复。不扫描外部目录。

退出公共宿主后分别复制音乐数据库所在目录（可排除 audition-cache）和用户选定的正式库。恢复时保持正式库的原路径。缓存可重新生成，Git 与正式安装包均不含用户曲库。

本地曲库将用户选中的音频原地索引到现有私有 SQLite，记录本机文件位置、标题、艺人、专辑、时长和可用性。首次打开新版会将旧库中已保留的正式歌曲加入索引。仅移除索引或清理试听缓存不会删除导入原件。备份需同时覆盖索引数据库、原文件及原有正式库；换盘后可从缺失条目的「重新定位」选择文件。

洛雪源及能力声明保存在音乐组件私有 SQLite。搜索仅发送当前选中的歌曲名和艺人，下载传所选版本及音质。源脚本在独立线程的 QuickJS 中执行，仅通过受限请求访问公网，无文件或通用 IPC 权限。遇到 198.18/15 代理虚拟地址时，使用 Cloudflare 的加密 DNS 重新解析域名。下载临时文件在所选目录内，校验格式和实际解码后独占发布并登记曲库。

模型凭据使用系统加密后按服务商存入组件私有配置，迁移到其他电脑或 Windows 账户后须重填。保存设置本身不调用模型。用户生成时才发送偏好和本次勾选的至多五条歌名、艺人；取消、鉴权失败或无效响应不会写入推荐记录。
