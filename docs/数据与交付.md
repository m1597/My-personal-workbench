# 数据与交付

## 存放边界

| 内容                       | 当前位置或约定                                                                                  | Git 与备份                                                    |
| -------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 源码、配置、文档与选定截图 | src、tests、scripts、docs、根配置                                                               | 提交后由 Git 记录，未 push 的 commit 仍只在本机               |
| 随应用发布的静态资源       | src/renderer/public                                                                             | 仅放可分发资源，不放私人素材或字体文件                        |
| 用户原始素材               | 原有外部素材库，或未来根目录 data/                                                              | 不移动现有素材，data/ 已忽略，单独备份                        |
| 应用设置                   | Electron app.getPath('userData') 内的 profile；Windows 默认基于 %APPDATA% 和应用名              | 当前主题和布局在该 profile 的 localStorage，不受仓库 Git 保护 |
| 浏览器预览设置             | 浏览器对应 localhost origin 的 localStorage                                                     | 与 Electron 设置独立，清理浏览器数据会丢失                    |
| 未来运行数据与日志         | 根 local/，日志可用 local/logs/，具体功能落地时再确定                                           | 已忽略，没有当前日志或数据库实现，不建空目录                  |
| 缓存                       | Electron profile 缓存、npm/Electron 自身缓存；项目 tmp/、.cache/                                | 可再生成，通常无需备份，不擅自改工具全局缓存目录              |
| 测试输出                   | test-results/production、development 的隔离 profile、trace、截图；playwright-report/；tmp/ 截图 | 已忽略，不上传 profile；报告可能含测试快照，只用合成数据      |
| 构建与依赖                 | out/、node_modules/                                                                             | 已忽略，可由锁文件与源码重建                                  |
| 备份                       | 根 backups/ 或独立磁盘/备份位置                                                                 | 已忽略，不把与原件同盘的副本作为唯一保障                      |

设置路径由 Electron 管理，不为了目录整齐搬动现有 profile。关闭应用后再备份需要保留的 profile 与素材，恢复前保留当前副本并核对版本。Git 不保存被忽略内容、外部文件和未提交修改；本地 commit 不等于远端或异地备份。本轮没有移动、删除或导入个人文件。

未来凭据只在受控主进程或执行环境读取，不写进 React bundle、shared、Git 或日志。目前无凭据需求，不添加假模板。以后确需 .env.example 时只写变量名与非真实示例；忽略规则不能撤回已跟踪的秘密。

## 依赖维护

1. 开任务记录，说明更新对象与原因；查上游变更、维护状态、引擎要求和许可证。
2. 在可回退提交基础上，一次更新一组相关依赖。用明确版本，例如 `npm install --save-exact 包名@版本`，开发工具加 `--save-dev`；同时提交 package.json 和锁文件。
3. 执行 `npm ci`、`npm run check`，UI 相关更新核对黑白截图。审阅 npm audit 和锁文件差异，不自动强制修复全部依赖。
4. 同步来源、环境基线、决策与任务记录，独立提交；主版本升级不与业务变动混合。

## 版本、未来安装包与回退

当前 0.1.0 为开发版本，不代表已经发布。准备可交付版本时明确验收范围，更新 package.json 与锁文件版本、变更说明和兼容性；通过验收后提交，再按用户确认的发布计划创建带说明的 vX.Y.Z tag。日常功能不必每次打标签，push 与发布分别授权。

首次分发时再选择打包工具，汇总实际运行依赖及完整第三方 notices（包括 Chromium、Node 和图标许可），核查字体和静态资源分发权；验证干净机器安装、启动、卸载和旧数据兼容。签名、自动更新、云端发布均未实现，本轮不引入相关服务或凭据。

代码回退优先 `git revert` 对应提交，保留历史，重新 `npm ci` 和 `npm run check`；不得通过破坏性操作清除用户成果。软件回退使用上一已验收版本，先备份设置和素材；未来数据库迁移要另设计恢复方案，不能假定降级代码自动回滚数据。

## 布局数据

键为 `workbench.layout`，值为 `{ version: 1, layout: Dockview序列化结果 }`。使用 Electron profile 的 localStorage（Windows 默认 `%APPDATA%/personal-workbench/Local Storage/leveldb/`，实际以 app.getPath('userData') 为准）；不在仓库内存放 JSON 文件，不由 Git 备份。浏览器预览、开发服务器 origin 与构建版 file origin 的存储相互独立，不自动迁移。更改应用名、profile 或开发端口可能使用新的设置空间。

正常关闭会同步更新 localStorage；强制结束进程、断电、磁盘不可写或清理 profile 不保证保留最新修改。存储异常仅警告，不阻断工作区。缺失、损坏、不支持版本、未知模块或不支持的浮动/弹出布局整体回退默认四模块，并在恢复完成后保存有效默认值；本轮不做部分迁移或坏数据备份。合法空布局不会触发回退。需要保留设置时，在关闭应用后独立备份 profile，不直接编辑 Chromium LevelDB 文件。
