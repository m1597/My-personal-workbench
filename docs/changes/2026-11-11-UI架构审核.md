# 2026-11-11 工作台 UI 架构审核

起点 aff572c，工作区、暂存区均干净。独立只读审核追踪代码与测试，主代理在独立 profile 复现，交接修正后由原审核者定向复核。

## 录像与窗口激活

录像 6.6 秒与 7.4 秒之间，中央面板的两个位置由蓝色和紫色同时变为相同中性灰；标题栏文字也变暗。变化跨越整个原生窗口。旧路径从工作台首次打开示例时先显示独立顶层窗口，再把视图移入工作台并隐藏那个窗口。离屏旧版实测两个 HWND，新版同操作只有一个。现有独立窗口成功停靠时，若来源仍持有焦点，宿主把焦点交给工作台。后台测试始终使用非激活窗口。Windows 会在窗口失活时回退桌面 Acrylic；录像记录了外观，未记录前台 HWND。重建后的真实 Windows 合成和焦点仍须人工观察。

## 一次操作的状态流转

| 阶段                       | 内容状态归属                                                                               | 布局修改与保存                                                                  | 取消或失败                                                                     |
| -------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 独立窗口进入目标，显示预览 | 示例 React 在同一个 WebContentsView 内持有输入、队列、计数；主进程持有视图、窗口、指针命中 | renderer 报可见区域，仅绘制预览，不写布局                                       | Esc、未命中或遮挡清除预览，原窗口保留                                          |
| 松手后等待槽               | 宿主持有交接编号及来源；Dockview 由工作台 renderer 单写                                    | 再验目标；先保存原布局并暂停后续写盘，复用、移动或新增槽                        | 已失效的组不改落点；5 秒超时撤回临时布局，原独立窗保留                         |
| 接入成功                   | 宿主收到本次槽与组的有效 bounds，移挂原视图并确认；已有来源隐藏                            | 工作台完成交接后恢复 250 ms 防抖保存                                            | 未确认期间卸载，按宿主记录确认或撤回，再立即保存，同时保留其他面板的已完成编辑 |
| 标签拖出工作台             | renderer 捕获标签指针，主进程复核整个系统窗口边框后移挂同一视图                            | 完成交接才清理原标签，正常防抖保存                                              | 工作台内拖动交给 Dockview；取消留在原处                                        |
| 关窗与重启                 | 只关工作台时示例可继续独立运行；整个宿主退出会结束内存会话                                 | 正常卸载保存分组、活动标签、尺寸；启动校验 v1，恢复有效旧布局、空布局及示例引用 | 旧最小尺寸可迁移，缺少示例宿主只移除该槽；损坏或不兼容布局回退默认             |

内置模块的独立窗由主进程 Map 按 ID 管理；它们重新挂载自己的 React 页面，模块 1 的搜索文字随交接传递。它们和原生示例共享命中规则与工作台布局写入器，内容生命周期各自独立。

## 实际样式来源

工作台产物的次序是 tokens → 公共 componentTheme → Dockview 包 → global → appearance。ComponentTheme 被入口依赖间接导入；Fluent 在运行时注入主题及控件样式。示例独立包导入公共主题和自身排版样式。检查的是产物次序、选择器优先级以及实际元素的计算值。

| 元素                     | 最终生效的规则                                                                                                              | 审核结论                                                                              |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 普通组与示例窗口底板     | componentTheme.css 的面板材质取 tokens.css 的 --panel-surface；embedded 根透明。appearance.css 的组阴影与圆角作用于面板边界 | 承载面各画一次。示例表单卡片的 glass 和描边只覆盖字段区，无法造成录像中整窗跳色，保留 |
| 队列列表和工作台菜单     | Fluent 提供键盘交互；component-popup 使用 --menu-surface、磨砂、选中背景。减少透明和强制色使用系统回退                      | 属于有意覆盖；原生窗口背景另由系统合成                                                |
| 恢复默认布局按钮、导航行 | 原先通用按钮选择器压过 primary-button 和 module-row。基线降权后主按钮使用 --accent，导航行恢复 flex-start 与自身间距        | 已用计算值和空布局按钮前后截图复验；保留 focus-visible 与禁用交互                     |
| 外壳背景                 | appearance.css 实际使用 --shell-surface；不支持 blur 的回退现在改变该变量                                                   | 删除被后加载背景覆盖的重复声明                                                        |
