## 需求与验收场景

- 普通修复：开发者可从开发流程判断只需更新任务记录，无须建立提案或 ADR。

- 交付：新增本地链接有效，Git diff 无空白错误；原有后台验证、独立 commit、不 push、桌面更新和保留配置规则仍可找到。

## 设计与取舍

借鉴 OpenSpec 将“当前规范”与“正在做的变更”区分的方式，但单项记录合并为一份 Markdown；不复制其完整目录、CLI schema 或斜杠命令，不宣称兼容 OpenSpec 工具。小改继续写任务记录。

ADR 先存于现有技术决策文档，用稳定编号和锚点检索；条目增长到不便浏览时再拆文件。已存在的组件框架设计保留详细方案，ADR 只记录选择与后果并链接它。

风险：多份记录可能再次漂移。以开发流程的文档职责表指定唯一事实来源，完成变更时更新对应现行文档。历史记录标注被替代而非悄悄改写。
