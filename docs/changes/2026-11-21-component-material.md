# 安装版组件同屏材质复验

以 v0.2.1 和桌面工作台 D:\FitBay\FitBay.exe 为起点。后台新建独立 profile，从组件菜单依次打开 Music、工具集、文件库，右下保留快速开始。复验使用同版本安装目录的隔离副本，载入重新构建的宿主、工具集和文件库。两次均由 Windows 捕获整个测试窗口，包含原生子视图。

| 四格相对采样坐标（从整窗左上起） | 原装 RGB   | 修复后 RGB |
| -------------------------------- | ---------- | ---------- |
| Music（47%, 7%）                 | 61, 63, 66 | 61, 63, 66 |
| 工具集（82%, 11.5%）             | 42, 50, 62 | 61, 63, 66 |
| 文件库（33%, 80%）               | 50, 56, 65 | 61, 63, 66 |
| 快速开始（92%, 83%）             | 60, 62, 65 | 60, 62, 65 |

采样值用于对照本机同一布局，桌面背景和系统合成会影响实际颜色。[原装四分屏](../images/component-material-021/before.png) · [修复后四分屏](../images/component-material-021/after.png)

- 停靠时，工具集 Shadow DOM 从宿主取得公共颜色，文件库按组件实际模式选择公共主题表面。三个组件根背景均为透明。将透明度、磨砂、亮度从默认值调至最低，三个渲染入口均得到相同的三个计算参数。
- 在该状态从文件库点击「独立打开」，独立窗口清除宿主材质覆盖；点击「加入工作台」重新取得当前宿主值。直接运行两个组件的安装版 EXE 也能显示相同的公共文字与控件配色。[独立工具集](../images/component-material-021/standalone-Toolkit.png) · [独立文件库](../images/component-material-021/standalone-Prompts.png)
- 后台复验命令为 `node scripts/check-installed-component-material.mjs "<包含三个已安装组件的工作台目录>"`。此次只使用隔离配置，未执行发行或用户覆盖安装。
- 原型构建、桌面启动脚本检查和相关 OpenSpec 严格校验通过。全库严格校验 50 项通过，既有 music-optional-plugins Purpose 长度警告导致 1 项失败。项目检查中生产交互首轮有一项布局恢复可见性断言超时，重跑 16 项通过；开发交互默认 5174 端口被占用，改用独立端口后 16 项通过。
