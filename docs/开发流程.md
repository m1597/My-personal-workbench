# 开发流程

## 已验证环境

Windows，本机 Node **24.19.0**、npm **11.17.0**。`.node-version` 和 `packageManager` 记录精确基线，`engines` 限定同一小版本；环境检查要求精确匹配。更换版本需重新验证并同步这些记录。它们不会替你安装 Node 或改全局配置。

首次或切换分支后执行 `npm ci`，严格按锁文件安装，包含 Electron 运行时下载；不要用 `npm install` 随意刷新依赖。需可访问 npm registry 和 Electron 下载站。安装工具优先放 D 盘，不由本项目自动修改系统路径。

执行 `npm run doctor` 检查版本、直接依赖、锁文件、Electron 二进制和必要文件；只读、不修复。失败时按 FAIL 行处理，再重跑；依赖不一致可先看 `npm ls --depth=0`。它不是编译或功能测试的替代品。

`npm run dev` 启动桌面开发；`npm run dev:web` 仅预览网页。`npm start` 会由 electron-vite preview 构建后启动，并不是安装包。

文本统一 UTF-8、LF、两空格；`.gitattributes` 管理 Git 换行，`.editorconfig` 管理编辑器。无需修改全局 core.autocrlf。

当前 Electron 45 不再自带 postinstall 下载；本项目显式配置 `postinstall: install-electron`，确保 npm ci 后 Electron 测试可直接启动。跳过安装脚本会导致 doctor 失败，可用 `npm run postinstall` 重试。参考 [Electron 变更说明](https://www.electronjs.org/docs/latest/breaking-changes)。

## 格式与静态检查

仅使用 Biome 2.6.6 格式化与静态检查，不叠加 ESLint/Prettier。`npm run format` 写回格式，`npm run format:check` 只检查，`npm run lint` 将警告也视为失败。锁文件交给 npm，截图和被 Git 忽略的目录不参与扫描。Markdown/YAML/HTML 按当前 Biome 支持范围处理；未支持的格式依赖 EditorConfig 与人工审阅。

启用推荐规则；测试允许非空断言（已有元素/几何验收）和 Playwright 必须的空 fixtures 解构；CSS 保留响应式/减少动态效果的 important 和互不重叠组件选择器顺序。不全局关闭可访问性规则；原生 dialog 的点击遮罩行为用局部说明豁免，键盘仍有 Escape 与关闭按钮。

`npm run typecheck` 以 strict 模式覆盖 src、tests 和根目录 *.config.ts。doctor 是直接运行的简短 JavaScript，受 Biome 检查；CI 的 YAML 不属于 TypeScript。当前配置共享 DOM/Node 类型；进程权限由运行时沙箱和架构约定控制，不把类型检查当权限控制。

## 一条命令验收

`npm run check` 依次执行 doctor → 格式 → 静态 → 类型 → 构建 → 发布及开发两套 Electron 交互测试。类型与生产构建各执行一次；开发测试另起 Vite 服务是验证开发行为所必需。只跑交互可用 `npm run test:interaction`（必须已有最新 out）；`npm test` 则先构建。测试使用隔离 profile，不触碰日常设置。

失败先看终端首个失败步骤。格式问题执行 `npm run format` 后查看 diff；类型/lint 按文件行号修正。测试报告使用 `npx --no-install playwright show-report playwright-report/production`（或 development）打开；原始结果分别在 test-results/production、development。手动启动的 Electron context 显式记录 trace，重启前后分别保存，失败截图与 trace 附在 HTML 报告；`npx --no-install playwright show-trace <trace.zip>` 可单独查看。trace 包含浏览器快照/网络，不等于测试断言记录，断言见报告。

GitHub Actions 在 push/PR 上运行 windows-2022，不需要另装 Playwright 浏览器。Node 基线从 .node-version 读取，npm 用 npx 在临时包缓存中调用指定版本，不安装全局 npm。权限仅 contents:read；失败上传报告/截图/trace，保留 7 天，不上传 profile。2026-11-09 用户授权推送后，[首次 Windows CI](https://github.com/m1597/My-personal-workbench/actions/runs/42599390733) 已通过；没有修改分支保护。Windows Server CI 无法验收 Windows 11 原生磨砂外观，仍需本机截图检查。

自动测试使用 WORKBENCH_TEST_BACKGROUND=1 将未打包测试窗口放在所有显示器左侧屏幕外，showInactive 且隐藏任务栏，不抢占桌面（完全隐藏会阻断原生拖拽）。正常启动与未来安装包不受影响。trace 关闭持续截图（实测会干扰开发模式原生拖拽），保留 DOM 快照与失败时单张截图。

## 日常小步提交

先检查 git status，阅读需求与任务记录，写明目标、范围、验收。每完成一项执行相应验证；代码交付使用 check，纯文档核对格式、链接和事实。同步记录和文档，审阅 git diff 与 git diff --cached，只暂存该事项，再 git commit，报告真实验证与编号。推送由用户另行明确，不改全局 Git 设置。

更新、版本与回退见 [数据与交付](数据与交付.md)。中断时保留进展和下一步，不把未完成事项标为完成。
