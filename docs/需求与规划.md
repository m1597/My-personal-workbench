# 需求与规划

## 已确认事项

- 项目为用户的个人工作台，预计会持续迭代，规模较大。
- 以网页为界面基础，希望尽量整合到一个软件中，便于构建自己的工作流、提高效率。
- 支持插件或模块扩展，设想包括音乐、3D 建模、平面设计和视频制作。
- AI 节点图模块最重要；用户以 Dify 为可能的参考，尚未确认采用任何现有项目。
- 各创作领域还需要类似资产库的组织方式；部分能力依赖商业软件，具体整合深度待讨论。
- 可以参考其他开源项目，具体项目与复用方式尚未选定。
- 每完成一个功能就创建一个 commit。

## 待梳理的产品设想

以下是后续讨论的记录框架，不代表已确认需求，也不要求一次性回答。

- **核心问题**：目前哪些工作分散、重复或难以管理？
- **典型流程**：打开工作台后，希望如何完成一件具体的事？
- **功能优先级**：首个版本必须具备什么，哪些可以之后再做？
- **使用环境**：主要在本机、浏览器、手机，还是多设备使用？
- **数据来源**：需要接入哪些本地文件、现有工具或外部服务？
- **数据边界**：哪些内容仅保存在本地，哪些可以同步到云端？
- **使用对象**：仅自己使用，还是未来需要多人协作？
- **实际约束**：对费用、网络、响应速度、备份和维护有哪些要求？

## 候选方向

以下为建议，尚未经用户确认；不是技术选型决定。

| 方向 | 适用场景 | 主要取舍 |
| --- | --- | --- |
| 网页工作台配合本地后台 | 先验证工作流，兼顾网页界面与本机文件、工具调用 | 需管理本地服务和浏览器访问权限 |
| 桌面应用承载网页界面 | 重点整合本机文件与创作软件，形成统一软件入口 | 增加安装、打包和更新维护工作 |
| 云端网页配合本机连接服务 | 多设备访问和远程任务较重要 | 认证、同步、网络和部署复杂度更高 |

建议优先讨论本地优先的桌面工作台；是否采用仍待确认。

## 设计建议（待讨论）

- 围绕项目组织文件、素材、工作流和产出，并提供跨项目搜索。
- 区分素材资产、工具连接与工作流：分别管理文件、软件能力和执行步骤。
- 统一软件入口与输入输出；不将所有第三方软件界面都能嵌入作为前提。
- 模块按能力提供内部界面、API/脚本连接或打开外部软件等接入方式。
- 节点图既需要编辑，也需要任务执行、状态反馈、失败重试、取消与人工确认。
- 运行记录关联输入、参数、工具信息与产出，支持追溯；大型素材优先索引原文件，减少重复复制。
- 首期只接通一条真实创作流程，再依据实际需要扩展插件接口。
- 复用开源项目之前核查实际接口、维护情况和许可证；目前未做项目选型调研。

## 阶段安排

1. **基础准备**：初始化仓库、协作约定和文档入口。
2. **方向确认**：梳理场景、比较方案、确定首个版本边界。
3. **最小版本**：实现并验证核心使用流程。
4. **持续迭代**：根据实际使用反馈完善功能与可靠性。
