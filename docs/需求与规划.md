# 需求与规划

## 已确认

- 单人、本地优先的个人工作台，通过模块组织创作工具与自己的工作流。
- Electron + React + TypeScript + Vite、Dockview；四个占位模块支持拖拽分屏、标签分组、尺寸调整、关闭重开、最大化和恢复。
- Fluent 固定深色玻璃；中文优先本机 HarmonyOS Sans SC，回退微软雅黑 UI。
- 布局自动保存位置、尺寸、分组、打开状态和活动面板；空布局有效。重置会持久化；损坏、未知模块或不兼容版本回退默认。最大化为临时状态。
- 每个完成事项验证后独立 commit；push 单独授权；调试默认后台。
- 工作台和业务组件分开安装、升级、卸载；第三方可按统一规范开发组件，无需下载其他业务组件。组件支持独立启动、加入/分离工作台、必要状态连续；音乐须避免重复播放/切换中断。卸载默认保留个人素材。
- 上述是已确认产品目标；已选择公共宿主方案 B，先验证示例，第一方音乐试听已获一期授权。正式安装升级待验证，音乐媒体会话见一期任务。

## 架构选择（已确认，分阶段验证）

见 [组件框架设计](组件框架设计.md)。用户已确认公共宿主 + 独立组件包。原生窗口拖入另行验证，按钮接入不代表拖入完成。

## 长期方向（尚未实现）

希望整合音乐、3D 建模、平面设计、视频制作与素材资产；AI 节点图优先级最高。商业软件可能通过外部接口或启动入口接入，不承诺全部界面嵌入工作台。

## 候选，尚待具体选择

- Dify 等项目可作为节点流程参考，未决定复用其源码。
- React Flow、SQLite、独立任务进程来自总体方案建议，未安装或实现；在对应功能启动时再确认版本、许可与执行方式。
- 项目资产索引、跨项目搜索、任务追溯、取消重试与人工确认，需从一条真实流程确定首期范围。

## 开发优先级

工作台固定使用原有默认深色玻璃。桌面入口已支持组件标题栏吸附与直接拖标签分离，后台验收记录见 [当前变更](../openspec/changes/dock-component-window/tasks.md)。

1. **补原型关键门槛**：在用户明确允许的前台时间或独立测试桌面验证真实标题栏拖入、停靠、分离、取消、遮挡、焦点及多屏 DPI；沿用隔离 profile。当前仅后台约束下保留此项待验，不能再用消息模拟宣布完成。验证结果决定是否继续采用现有实现路线。
2. **再考虑正式交付验收**：UI 稳定后另行安排重建安装包、隔离环境真实安装/覆盖升级/卸载保留数据与回退；桌面源码预览更新不代表安装包已更新。远程 CI 需单独 push 授权，不是本轮前置阻塞。
3. **最后再规划组件生产化**：基于原型门槛证据，写变更记录细化正式宿主分发、协议兼容、数据单写入、布局迁移与权限边界，重大方案先确认。音乐会话现由第一方组件实施，验收见 [音乐试听一期](../openspec/changes/add-music-recommendation-audition/tasks.md)。

第一方音乐试听已获一期授权；其他资产模块、AI 节点图、通用数据库层、SDK、插件市场、自动更新亦未进入实施。具体业务功能按后续确认的范围启动。

本地曲库已纳入音乐组件；用户手选文件或目录，原地索引并播放。范围和验收见 [本地歌曲库一期](../openspec/changes/add-local-music-library/tasks.md)。

本地曲库支持导入用户自选的洛雪兼容源，根据选中歌曲匹配在线版本并下载到指定目录。协议覆盖和操作见[组件开发](组件开发.md#洛雪音乐源)。
