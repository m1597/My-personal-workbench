# 可独立分发组件：架构评估与最小验证计划

状态：产品目标已确认；本文架构与协议为提案，待用户确认。日期：2026-11-09。本轮只调研和整理文档，不安装依赖、不改运行代码、不开发音乐库。

## 结论与需要确认的选择

推荐 B：可独立安装的公共组件宿主 + 分开分发的组件包 + 可选工作台界面。宿主负责窗口、受限能力、会话和安装登记，工作台保留 Electron/React/Vite/Dockview/Fluent，作为同一宿主可打开的工作区界面。组件独立窗口不是工作台的隐藏页面，也不需要下载音乐以外的业务组件。

这一选择明确意味着：仅使用音乐组件时无需安装工作台界面，但必须安装公共宿主；组件安装器可提示并引导安装匹配宿主，离线场景提供“宿主 + 当前组件”的组合分发。公共宿主不是操作系统服务，按需启动；不能将“没打开工作台”宣传成“没有公共运行时依赖”。若用户要求组件安装后完全不依赖任何公共宿主，则选择 A，并接受重复运行时和跨应用界面重建成本。

批准后先做可丢弃的示例验证，尚不承诺 WebContentsView 与 Dockview 的视图移动和原生拖入已经可用。最关键门槛是原生视图与 DOM 布局的遮挡/焦点兼容，以及切换时媒体会话连续性。门槛失败应回到设计选择，不直接写音乐库补救。

## 两种可行路线比较

| 维度       | A：独立应用 + 可嵌入 Web 界面/协议                                                                                                    | B：组件包 + 通用宿主（推荐）                                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 安装内容   | 工作台自身 Electron；每个应用含后端、独立 UI、可嵌入前端与启动器。用 Electron 开发的每个应用通常各带一份 Electron；也可用其他原生技术 | 宿主安装包含 Electron、能力代理与窗口管理；工作台包含布局外壳；组件包只含自身前端/受限后台/资源/清单。每兼容宿主主版本一份运行时，不随每个组件重复携带 |
| 独立运行   | 各应用自行持有主进程、UI 与后台；无需工作台或公共宿主                                                                                 | 公共宿主主进程创建组件独立窗口与隔离 renderer；无工作台窗口也能运行。宿主必须先可用                                                                    |
| 嵌入       | 工作台新建隔离网页视图加载组件提供的嵌入 UI，连接原应用后台。原应用后台继续运行                                                       | 宿主把同一组件会话的 WebContentsView 移至工作台面板对应区域；Dockview 管位置，宿主管视图                                                               |
| 界面转移   | 不能把另一 Electron 主进程的 WebContents 当对象移入。一般重建 UI、传递视图快照和订阅后台；原窗口在新 UI ready 后隐藏/销毁             | 同一 Electron 主进程可管理两端视图，优先移挂同一视图以保留 DOM；仍需验证 API 组合。必要时重建 UI，但后台会话不重建                                     |
| 播放/队列  | 必须归属独立应用的稳定后台；嵌入 UI 不播放第二份。若声音只在旧 UI，隐藏/销毁会有中断风险                                              | 属于组件唯一持久会话/受控媒体执行上下文，独立于可移动 UI；同一宿主单实例协调                                                                           |
| 退出/崩溃  | 组件进程崩溃只使该组件断连；工作台仍工作；工作台退出不终止独立应用                                                                    | 组件 renderer/执行上下文崩溃不应杀死宿主；宿主主进程崩溃仍影响全部窗口，这是共享运行时的故障范围                                                       |
| 升级/卸载  | 每个应用负责自己的升级；宿主按协议拒绝不兼容连接；不能保证第三方安装器尊重数据约定                                                    | 注册表选已验证版本；有活跃会话延迟切换；组件数据与包分开；工作台卸载不卸载公共宿主或其他组件                                                           |
| 资源和体积 | 自包含体验明确；多个 Electron 应用磁盘和后台基线通常更高，具体数值需测量                                                              | 节省重复磁盘运行时；每组件仍有隔离 renderer/会话成本，不宣称只占一个进程或零开销                                                                       |
| 开发/兼容  | 应用内部技术自由，协议适配和双端 UI/进程协调复杂；更适合接入已有应用                                                                  | 组件开发较简单，集中承担宿主版本与安全维护；组件需输出浏览器可运行界面，不要求 React                                                                   |
| 跨平台     | 本地 socket、安装发现需各平台实现；原生外部窗口重挂并不跨平台                                                                         | Electron 窗口/视图基础跨平台；仍须逐平台验收 DPI、输入法、窗口拖动，不能从 Windows 推定 Wayland/macOS                                                  |
| 安全       | 普通独立 exe 具有当前用户 OS 权限，协议只能限制宿主授权，无法限制 exe 自己访问磁盘；不能把它列为默认安全第三方包                      | 默认仅受限 Web 包，无任意 Node/本地 exe。能力由宿主代理授权；未来原生插件必须另行定义 OS 沙箱或高信任安装模式                                          |

A 的建议连接方式是同用户本地命名管道（Windows）/Unix socket（其他平台），采用长度前缀 JSON 消息；嵌入资源优先由宿主校验安装目录后提供，若用 localhost HTTP，须绑定回环、随机端口、逐会话鉴权与 Origin/Host 校验，不能开放无认证服务。没有必要先引入 WebSocket 服务框架。Node net 提供传输，不提供完整身份认证。[Node IPC](https://nodejs.org/api/net.html#ipc-support)

原生 HWND SetParent 等“把任意软件窗口塞进来”的路线不推荐：焦点、DPI、窗口所有权、进程权限和跨平台不可统一，且不能迁移应用状态。未来已有第三方原生应用可只做启动/协议连接，不承诺停靠。该范围不同于本产品按规范开发的可停靠组件。

## 推荐方案的进程与界面关系

```text
公共宿主（同用户、同兼容主版本一个实例；无窗口时按需退出）
├─ 可信 main：登记、授权、会话管理、窗口/视图管理、受限数据代理
├─ 工作台 renderer：React + Dockview + Fluent（可不加载）
├─ 组件 X UI：sandbox WebContentsView（独立窗口 ↔ 面板区域）
├─ 组件 X 会话：独立受限执行上下文/媒体上下文（不跟着 UI 销毁）
└─ 组件 Y UI/会话：与 X 分开分区、能力令牌及数据域
```

工作台和组件都是可选安装内容，不是从工作台源码复制出来的两个应用。公共宿主自身是需要维护的产品边界，本轮不创建其工程或 monorepo。

Dockview 面板内放可信的“视图槽”，由宿主按可见标签、面板矩形和窗口 DIP 坐标摆放 WebContentsView。分屏/缩放事件合并更新 bounds，非活动标签隐藏视图。Fluent 菜单/弹窗和 Dockview 拖拽提示属于 DOM，原生视图可能盖住它们：须设计宿主遮罩/临时隐藏或独立覆盖层，验证窗口内遮挡、裁切、焦点、中文输入法和无障碍；CSS z-index 不能直接解决。这是推荐路线最大的 UI 工程风险。

备选呈现方式是受限 iframe 中重建 UI，后台保持唯一：更容易贴合 Dockview DOM，但不能假定跨窗口移 DOM 保留上下文。只能在安全边界与媒体连续性验收通过后改用；不同时建设两套系统。Electron webview 标签不作为首选，采用官方 WebContentsView 或评估后的受限 iframe。[WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view)、[View](https://www.electronjs.org/docs/latest/api/view)、[BaseWindow 资源管理](https://www.electronjs.org/docs/latest/api/base-window#resource-management)

## 音乐连续性与生命周期

音乐尚未实现，以下是约束而非已验证能力。queue、trackId、position、播放时钟与音频输出归属于唯一组件会话；视图仅发命令和展示状态，不在组件 mount 时自动启动音频。实际音频 API 往往需要 renderer 媒体上下文，不能想当然放进 Node utilityProcess；首个样例用合成音频验证不重建播放器，并保留独立后台计时/队列真源。后台隐藏、节流和系统休眠要单独验证。

生命周期：installed → stopped → starting → ready-detached ↔ attaching → ready-docked ↔ detaching → ready-detached；任一运行阶段可进入 disconnected/crashed，不能卡死整个工作台。

一次 attach/detach 使用 transferId 与 sessionId：prepare（记录视图状态、冻结重复切换命令）→ 目标槽/窗口 ready → 同一视图移挂或新 UI 订阅既有会话 → ack revision → commit 所属窗口 → 释放旧视图。超时/cancel/失败恢复旧视图；目标尚未 ready 不能先销毁源。命令按 requestId 去重，重连快照不触发 play。关闭标签默认只关闭视图，不等于停止后台；仍有播放时显式告知继续/停止策略。关闭工作台将活跃组件分离；“退出组件”才停止其会话并持久保存；“退出全部”需处理未保存状态。

组件 UI 崩溃时显示可重载占位，后台若存活继续播放；后台崩溃后恢复队列与最近检查点但不自动重新播放，避免惊扰或重复音轨。宿主崩溃不承诺音频不中断；保证的是正常形态切换，不能把故障恢复当无缝播放。

## 最小规范草案（协议 0.1，未实现/未发布 SDK）

### 清单与安装发现

清单至少包含 manifestVersion、反向域名 componentId、展示名、SemVer version、protocolRange、hostApiRange、uiEntry（包内相对路径）、可选 sessionEntry、modes=[standalone,docked]、stateSchemaVersion、capabilities、支持 OS/arch、许可证与发布者标识。例 ID：io.example.counter；ID 不是信任凭据，同 ID 不同发布者不可静默替换。包入口必须在包根内，拒绝绝对路径、..、符号链接/解压路径穿越和远程可执行入口。

版本独立：组件版本、协议版本、宿主 API 版本、状态格式版本不混用；协议 0.x 次版本不兼容默认拒绝，1.x 后主版本决定破坏性兼容；握手取双方支持交集，未知必需能力拒绝。不用 Electron 版本号冒充组件 API 稳定承诺。

安装器/导入动作显式登记到宿主管理的当前用户目录，不递归扫描磁盘或私人素材库；原型先用用户指定 manifest 路径。登记存 ID、版本、规范化安装路径、内容摘要、来源/批准状态，摘要用于完整性而非身份认证。安装位置可选 D 盘，注册和数据目录分别管理。公共宿主检测已安装组件；只缺宿主时组件提供清晰安装指引，不偷偷装整个工作台。

独立快捷方式调用宿主 --component <id>；已有宿主时经受控单实例通道转交，不产生第二个数据写入进程。协议 URL 可以后增加，不是首轮必需。只在固定登记目录刷新，缺目录标为 unavailable，不执行猜测路径。

### 能力、安全与消息

默认能力仅 UI 渲染、自身命名空间设置和生命周期；素材访问必须经用户选择授权的目录句柄/不透明资源 ID；共享资产通过受限 broker 查询/读取，写入和删除另行授权。网络按批准域名，拒绝未声明下载、麦克风/摄像头、任意 shell、任意文件读取、任意 IPC 和其他组件存储。

宿主自己提供 preload，不执行包自带高权限 preload；nodeIntegration=false、contextIsolation=true、sandbox=true，独立 session partition 与组件 origin，自定义协议路径限制、CSP、导航/新窗口拦截、permission request/check 默认拒绝。权限检查在可信 main，校验真实 sender/webContents/frame 绑定的组件与会话，不信任消息里自报 componentId。所有参数运行时校验、长度/频率/超时限制；日志去掉令牌和私人路径。partition 是存储分区，不是完整隔离。独立进程/TypeScript/iframe 都不自动提供完整沙箱，Electron/Chromium 漏洞和主进程 broker 缺陷仍有风险。

第三方默认只允许浏览器/WASM 可运行的受限包，后台同样不能是任意 Node；Node utilityProcess 提供故障分离而非 OS 权限隔离。自带 exe/Python/原生库需要额外高信任模式或真正 OS 沙箱，本阶段不开放，不能用权限声明掩盖其实际磁盘权限。[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)、[utilityProcess](https://www.electronjs.org/docs/latest/api/utility-process)

统一语义消息 envelope：protocol、requestId、sessionId、generation、type、payload；响应含 ok/result 或 error{code,message,retryable}，事件带 revision。握手 hello/welcome 交换版本和已授予能力，绝不传全局密钥。最小消息为 session.open/close、view.attach/detach、state.snapshot、command、event、ping/pong、error。错误枚举含 NOT_INSTALLED、INCOMPATIBLE、DENIED、BUSY、CRASHED、TIMEOUT、STALE_REVISION；有可读说明与重试/移除占位入口。首版单连接按顺序，requestId 缓存去重，generation 拒绝旧连接写入，状态命令必须带 expectedRevision。

B 内部优先 Electron 受限 IPC/MessagePort，通过宿主路由；端口只给被批准视图并在退出时撤销，不能因为拿到端口就授权全部方法。A 通过本地 socket 适配同一语义；校验端点归属、同用户 ACL/访问模式与会话令牌，不把随机管道名当认证。不同已启动 Electron 主进程不能直接共享 MessagePortMain 对象。[MessagePorts](https://www.electronjs.org/docs/latest/tutorial/message-ports)

### 数据归属、升级与布局

提议目录是逻辑约定，确认/原型前不创建：宿主设置/登记在独立 Host userData；组件包在可选安装根 components/<id>/<version>；私有可写数据在 ComponentsData/<id>；公共资产仍在用户选择的外部素材根，通过资源 ID 授权；缓存/日志另分目录。宿主卸载、工作台卸载、组件卸载均默认保留私有数据和原始素材；只有独立明确“删除数据”操作可删除，权限不可由组件卸载脚本扩大。

一个 componentId + dataProfile 对应唯一会话写者，多个视图都通过它写；锁跨兼容宿主版本有效。用 OS 可释放锁或等效进程所有权锁，不能仅凭残留 PID 判断；抢锁失败连接原会话或只读，不并发写。UI 快照只存筛选、选择、滚动等瞬态状态；队列、播放会话和资产元数据由组件会话保存。原型 JSON 原子替换足够，不提前数据库；实际音乐数据方案随后定。

升级用版本目录并存 → 校验清单/能力差异 → 停止或等会话退出 → 迁移检查点 → 原子切换登记；失败回旧代码及兼容数据副本。未提供可回退迁移时不承诺降级读取新数据；新增权限需重新授权。卸载只移除登记/包和快捷方式，运行中先正常停止，不能边播放边删二进制。宿主卸载单独操作，告知仍依赖它的组件，不随工作台卸载级联删除；兼容主版本可并存但不得同时写同一组件数据。

布局 v2 保存 Dockview 网格及 panelId → {componentId, instanceId, viewId, stateRef}，不放完整队列、令牌或素材路径。恢复先创建可信通用组件槽，再解析登记；未安装/已禁用/不兼容显示原位置占位，其余组件继续恢复。结构真正损坏才回默认；合法空布局继续保持，最大化仍不恢复。v1 四模块可确定迁移到内置模块引用；迁移前保留 v1 副本，失败不覆盖旧值。Dockview 的浮动/弹出描述和组件 standalone 状态不是同一概念，应由生命周期协调，不仅保存 window.open 的坐标。

## 批准后最小验证与停止条件

原型先以单个 examples/sample-component 实际文件目录组织，通过独立命令生成组件部署包；宿主试验可在任务分支中渐进做，不提前大型 monorepo/发布 SDK。示例包含计数/输入/滚动状态、合成音频和小型队列，不使用私人音乐素材，不开发音乐库业务。

| 阶段            | 验证动作与验收证据                                                                                                                  | 失败时处理                                                                      |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| P0 分开部署     | 宿主、工作台包、示例包分开目录与清单；无工作台包时启动示例，工作台单独启动不加载示例；记录包清单/启动依赖                           | 如果必须复制整个工作台或下载全部组件，方案不合格                                |
| P1 发现/连接    | 只登记指定示例，检查握手、权限拒绝、缺失入口、协议不兼容；不扫描用户目录                                                            | 给具体错误，不自动执行未知包                                                    |
| P2 按钮生命周期 | 加入工作台/分离窗口反复 20 次；保持 sessionId、输入、选择、队列和播放计时，不重复创建播放器；先测视图移动，再测焦点/遮挡            | 视图与 DOM 层级失控则停止音乐开发，评估 UI 重建备选；按钮成功不等于拖入成功     |
| P3 故障与资源   | 杀示例 renderer/后台而不杀工作台；关闭工作台仍可用示例；拒绝重复写者；禁用/卸载后布局占位保留；重复开关检查进程/监听器数            | 连带崩溃或错误权限必须先修复；共同主进程故障单独记录                            |
| P4 原生拖入     | 用户可见的独立组件窗口标题栏移入工作台，检测停靠区域/释放/取消，真实移动而非截图模拟；测试125%/150%、多屏负坐标、窗口遮挡、缩放切换 | Windows move 事件与释放判断待验证；原生拖入未通过则明确未实现，不以按钮验收替代 |
| P5 独立安装     | 各自安装/升级/卸载，工作台卸载不删组件/数据，组件卸载保留素材；测试无工作台包、仅宿主依赖环境                                       | 首轮可用部署验证，不把部署称作真实安装验收；正式安装需隔离 Windows 环境         |
| P6 开发者接入   | 可运行示例 + 简短开发说明 + 清单/协议约定 + 开发/独立/接入/失败验证命令；第二种 UI 技术或最小纯 HTML 验证不绑定 React               | 实际跨仓库需要出现后才讨论 SDK npm 包或仓库重组                                 |

播放验收需记录唯一音频 owner、切换前后 position/queue revision 和单调时钟，另测实际合成音频采集中的空洞/重复；单纯计时器没有重置不能证明听感无中断。后台自动化不得出声干扰用户，音频路由/采集使用隔离环境；若没有条件，标注该项待验证，不能宣称音乐无缝切换。

自动化使用独立 profile，在后台运行；真实原生拖窗与系统级安装/卸载放隔离桌面/VM，无法后台无干扰验证时另约用户验收，不修改当前 Windows 缩放。真实原生 Acrylic 与输入法体验仍需桌面检查。每个独立验证事项通过后 commit，不 push；不加入市场、账号、支付、复杂自动更新或远程执行。

## 本轮证据与决策门

已验证：当前工程假设、Git 状态、已有代码和配置；本轮只文档，格式/链接/差异检查另见任务记录。依据官方文档推断：同一宿主可管理组件视图与窗口，公共宿主可减少重复运行时，独立应用可通过协议提供第二个 UI。待原型验证：WebContentsView 实际移挂、音频连续性、Dockview 原生视图覆盖、跨窗口焦点、原生拖入、多版本数据写锁、真正安装卸载和性能。

待用户确认的核心取舍：是否接受 B 的公共宿主依赖（无需工作台界面），以换取组件小包、统一能力边界和同会话切换。确认后仅启动 P0–P2 示例验证；P4 原生拖入单独验收。若要求组件完全自包含，则改走 A，并重新确认运行时重复和后台安全信任范围。
